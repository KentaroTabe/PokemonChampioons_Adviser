# プロジェクト現況 — 現状・課題・対応策 (2026-09-05 朝 更新)

ポケモンチャンピオンズの対戦画面を解析し、リアルタイムで行動アドバイスを返す
エージェント。本書は**現時点の全体像を1枚で把握するための総括**で、
詳細は末尾の索引から各文書へ辿る。日付つきの数値はすべて実測値。

---

## 1. 全体像

```
配信画面 ─→ vision/ (シーン判定・OCR・救出バッファ) ─→ 対戦状態
                                                          │
使用率DB (championsbattledata + pokedb) ─→ 型予測 ─────────┤
                                                          ▼
                 advisor/ (ダメージ計算 + 択の期待値探索 + RL方策ブレンド) ─→ 提案
                                                          ▲
champions_agent/ (自己対戦PPO・選出モデル・構築進化探索) ──┘
```

3つの独立した学習問題として扱う (2026-07-29 に確立):

| 層 | 手法 | 現在の状態 |
|---|---|---|
| 操縦 (3体で戦う) | 探索/期待値核 + MaskablePPO 自己対戦のブレンド (配布は EMA 方策) | h2h vs 3_best **0.566** (9/2、18,000戦) |
| 選出 (6→3体) | 勝率回帰 + argmax | ゲート通過済み (分割依存の揺れは要観察) |
| 構築 (6体) | 使用率メタ + 進化探索 + 対応評価 | 推奨構築を決定済み (§2.4) |

設計判断の根拠は README「設計判断」節、詳細は ARCHITECTURE.md。

## 2. 現状 (実測)

### 2.1 画面認識
- メッセージは演出中1〜2秒で流れ、負荷時にフレームの **54〜76% が破棄**される。
  「読んで更新する」だけの設計は原理的に不完全と判断し、
  **決定的反映 (技・交代・持ち物効果表) / 救出バッファ (軽量トリガー+非同期OCR) /
  定点照合 (残数ボール・交代メニュー)** の三層へ移行済み (8/31)。
- 認識は「精度」でなく**「提案への影響」で評価**する。決定再生ハーネス
  (`scripts/advice_replay.sh`、120決定点) の推奨反転率:
  自分HP固着 28.1% / 相手判明技消失 23.9% / 相手HP固着 20.7% /
  選出フラグ消失 18.9% / 相手ひんし見逃し 10.2% (高マージン反転 0)。
  **認識への投資順はこの表に従う。**
- 型登録は対戦中「もっと見る」・選出画面・パーティ管理画面の3経路 (対戦状態と分離)。

### 2.2 学習・測定
- 事前登録判定を3件実施: P1 アンカー常駐 **棄却** (+0.092 < +0.10)、
  P5 EMA配布 **採用** (+0.027、z=5.3)、P4 探索ε **棄却** (0.5662、基準比 −0.040)。
- 判定のたびに評価軸の回転 (cbd型の日次回転、名寄せ修正) が問題になった。
  **9/2 に評価側の meta_sets ピン (META_PIN=24) を導入**し、ラダーの POOL_PIN と
  合わせて評価軸を固定した (学習は最新メタを追う)。9/3 の初回測定を新基準にする。
- 学習は常時稼働 (ko報酬、N_ENVS=4、探索ε0.20、selfplay枠0.45)。
- **信念つき探索の判定 (9/4、docs/BELIEF_SEARCH_PLAN.md)**: 外部フィードバックを事実確認して
  P7→P6-a→P6-b→P8→P9 を事前登録・実装・測定。探索プレイヤー各300戦・同一相手列で
  P7 多世界探索 **棄却** (0.380 vs 単一仮定 0.413)、P6-a RL価値の葉評価 **維持** (0.547 vs 0.420)、
  P6-b 相手行動の事前分布 **棄却** (0.503 vs 0.510)。**アドバイザー自身の対戦強度を初計測: 0.59**
  (advisor-as-player、300戦)。発見: 助言の推奨は探索結果を使っておらず (択評価は表示専用)。
  P8 センサ世界 **棄却** (雑音下 +0.017±0.040)、P9 探索値の統合 **棄却** (各600戦 +0.037±0.026、
  ゲート未達。点推定は一貫して正)。
- **9/5 (シーズン切替前)**: P10 技イベントの期待ダメージ推定 **棄却** (シムの固着ノイズ下で
  0.535 vs 0.568、既定OFF。同一設定の走行間差 0.078 で「雑音の害」の前提が再現せず)、
  P7' 観測更新つき多世界 **棄却** (+0.003±0.039)、P9' 統合 (各1,500戦・同時起動) **棄却** (−0.007±0.017)。
  **測定の交絡を発見**: アドバイザー/葉評価は起動時の EMA 方策を読み学習で動くため、時刻差のある腕は
  後の腕が有利 (第1回 P9 の +0.05 の正体)。以後は腕の同時起動と `scripts/pin_models.sh` の
  ピン止め (rl_bridge も CHAMPIONS_MODELS_DIR を尊重) を規則化。同一設定の走行間差は 300戦で
  ≈0.03〜0.08 → 腕の既定を 600戦に。

## 4. 本総括で実施した改善 (2026-09-02)

1. **評価軸の meta_sets ピン** (`META_PIN`) — 3回の判定すべてで問題になった軸回転の
   根本対策。評価だけが固定スナップショットを使い、学習は最新を追う。
   評価結果に `meta_snapshot` を記録 (tests/test_meta_pin.py)
2. **Showdown の切り離し起動** (train_nightly → ensure_showdown.sh) と
   **evolve の Showdown 不在時の明示中止** — 当日の巻き添え事故の根本対策
3. **`scripts/stop_training.sh` / `start_training.sh`** — 起動停止をスクリプト経由に統一
4. **`scripts/ci_local.sh`** — CI同等条件 (コミット済みファイルのみ) の検証
5. Actions を v7 へ更新 (次回 push で検証)
