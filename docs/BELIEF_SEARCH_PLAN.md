## 1. 事実確認 — フィードバックの前提 vs 実装の実態

| フィードバックの前提 | 実態 (確認箇所) | 帰結 |
|---|---|---|
| 型予測は「一番ありそうな型」を1つ決める | **仮説分布は既にある**: `advisor/ev_infer.SpreadEstimator` が性格×配分×持ち物の仮説集合を対数重みで保持し、整合性・行動順 (×4/×0.1)・被ダメージで更新する。ただし意思決定側は `best_for()` の**点推定だけ**を探索へ渡す (`advisor/engine.py:301`)。技は `SetPredictor` の周辺分布 | 提案①は「分布を探索に流す」だけで着手できる。最小コストで最大の提案 |
| 探索/期待値核と PPO を最後にブレンドしている | 最終ブレンド (`rl_bridge`) に加え、**RL価値関数の葉評価は既に配線済み** (`engine.py` の `leaf_fn`、モデルがあれば常時有効)。ただし探索プレイヤー (`search_expert`) での実測は価値ブレンドが**逆効果** (0.44→0.34、報酬スケールの較正不良、2026-07-27)。アドバイザー経路の葉評価の効果は**未測定** | 「RLを探索の中へ」は既に半分入っており、効かせるには**較正**が先 (P6-a) |
| 次候補は v7 set encoder | **8/14 無益性棄却、8/17 v7観測+MLP も棄却** (−0.130、95%CI −0.144〜−0.116、docs/RL_V7_SET_ENCODER_DESIGN.md)。総括文書が「次候補」と誤記していた (本日訂正) | 提案④はそのままでは再挑戦しない。役割 (探索の事前分布/相手モデル/価値) を変えるなら別の設計として事前登録 |
| 探索が核で強く、NN は補正役 | 純探索 (同時手番の利得行列+2手読み、ロール3群) 単体は bench **0.41〜0.44**、PPO方策は **0.56〜0.62** (`search_expert` docstring の実測)。Laplace 型の深い MCTS は無い | 本プロジェクトでは核は現状 PPO の方が強い。探索内へRLを入れる価値は、探索自体の深さ/幅の強化と一体でないと出にくい |
| 相手最善応答 (minimax) に寄りがち | 既に **期待値 (相手行動分布で加重) と保証値 (minimax) の動的ブレンド** (`RISK_WEIGHT` 0.4、優勢時 0.6) と択リスク表示がある (`advisor/search.py`)。CVaR・仮説間分散は無い | 提案⑤は拡張として妥当 (P7 の副産物で仮説間分散が取れる) |
| 推奨は1位だけ | 上位3行動を 期待/保証/最悪応手つきで出している。条件付き推奨・安定度は無い | 安定度と「型依存」の表示は P7 の副産物 |
| churn 対策はヒステリシスのみ | 正しい (`advisor/service.py` margin 6.0) | 安定度 P(argmax不変) で一段進める |
| h2h 0.566 がブレンドの性能 | **誤り**。0.566 は PPO方策 current の学習評価 (h2h vs 3_best)。**アドバイザー (探索+RL) 自体の対戦強度は未測定** | 測定基盤の欠落。advisor-as-player の評価経路が要る (§4) |
| LLM をターン内に置かない | 既にそう (LLM は監査 `tools/audit_subtask` のみ) | 変更なし |
| ノイズ注入シム評価は予定段階 | 決定再生ハーネス (8摂動・推奨反転率) は実装済み・オフライン。シム内注入は未 | P8 の測定に既存ハーネスを使う |
| Laplace 2231 Elo 等の外部数値 | 未確認 (本書では根拠に使わない) | — |

結論: フィードバックの**方向 (belief → 多世界探索 → 集約 → 助言/エージェント) には同意**する。
ただし着手順は実態に合わせて **P7 (belief を探索へ) → P6-a (価値較正) → P6-b (相手行動の事前分布) → P8 (センサ不確実性)** とし、ネットワーク変更は役割が決まるまで行わない。

## 2. 目標像

```
観測 ─ 確率的状態 ─ 相手 belief (K仮説) ─┬─ 世界1 ─ 探索 ┐
                                          ├─ 世界k ─ 探索 ├─ 集約 (期待値/保証値/仮説間分散/安定度) ─ 助言
                                          └─ 世界K ─ 探索 ┘
                                                 ↑ RL: 相手行動の事前分布 / 較正済み価値 (葉)
```

同時手番・確率的結果・多世界を扱う探索を核に、RL は「探索を助ける事前分布と価値」として使う。
アドバイザーとエージェントは最後の1層 (推奨+安定度+仮定 vs 行動サンプル) だけを変える。

## 3. 実験の事前登録ドラフト (着手前に training_changes.json へ登録する)

すべて固定軸 (META_PIN=24 / POOL_PIN) で測り、主要指標は「同一窓の候補−基準の差」。

### P7 — belief-weighted search (最初に着手)
- **変更**: `engine` の `best_for()` を、`get_tracker()` の重み上位 K 仮説 (K=8、重み正規化) に置き換え、
  仮説ごとに同じ探索を実行し、行動ごとの期待値を重み平均する。
  副産物: 安定度 = Σ_k w_k·1[argmax_k = argmax]、仮説間分散、「仮説 n/K で安全」の説明文。
- **測定1 (対戦強度、シム)**: `search_expert` に同じ belief 経路を通し、`tools/check_search_expert` で
  点推定 vs belief を各300戦・同一相手列 (opp_seed 固定)。**ゲート**: 差 ≥ +0.05 かつ 95%CI下限 > 0
  (探索プレイヤー単体の基準 0.41〜0.44 を同日に再測する)。
- **測定2 (助言の反転率、オフライン)**: `scripts/advice_replay.sh` の8摂動で点推定 vs belief の反転率を比較。
  特に「相手判明技消失 23.9%」「相手持ち物消失」が下がるか。
- **レイテンシ**: p50/p95 を同時計測 (探索コストは K 倍)。上限は実測で決める (救出バッファの
  フレーム処理と競合しない範囲。目安 p95 < 1.0s)。

### P6 — RL統合方式
- **P6-a 価値較正**: 現行の葉評価 (常時有効) を with/without で測る (`check_search_expert --no-value` 相当を
  アドバイザー経路でも)。逆効果なら bench 勝率への較正 (Platt) を入れるか無効化する。
- **P6-b 相手行動の事前分布**: `opp_move_pool` の使用率重みを、自己対戦方策 (EMA) が相手の立場で出す
  行動確率と混合 (λ を事前登録)。測定: `search_expert` vs bench と h2h。
- **P6-c 自分側の事前分布**: 探索候補の初期順位/剪定に方策確率。2手読みでは候補が少なく効果は薄い見込みで、
  深さ拡張とセットで検討。

### P8 — sensor-aware search
- 状態に信頼度 (HP幅、技観測確率、選出確度) を持たせ、**反転率の高いフィールドだけ分岐**する
  (decision-aware expansion。感度表: 自分HP固着 28.1% / 相手判明技消失 23.9% / 相手HP固着 20.7%)。
- 測定: 決定再生の摂動下の反転率と、シム内ノイズ注入 (HP±5%、技欠落) 下の勝率。P7 完了後に設計する。

### 蒸留 (Metamon の代替)
- 探索教師→方策蒸留は `train/bc_pretrain --teacher search` として基盤がある。ただし教師 (探索) が
  方策より弱い間は無意味 (0.44 vs 0.56〜0.62)。P6/P7 で探索が方策を上回ってから。

## 4. 追加する評価指標

| 指標 | 現状 | 追加方法 |
|---|---|---|
| Cross-play matrix (current/best/EMA/探索プレイヤー/ヒューリスティクス) | 3性格_best との h2h のみ | `evaluate` の agents/benchmark を組み合わせる新ツール。自己対戦の循環 (じゃんけん) 検出用 |
| Advisor-as-player の対戦強度 | **無い** | アドバイザー経路 (belief+探索+RL) をプレイヤーとして bench/h2h で測る。P7 の測定1がその第一歩 |
| Recommendation stability / 仮説間分散 | 無い | P7 の副産物を advice payload に追加し、監査で集計 |
| Regret (探索最善との差) | 無い | 決定再生で算出 |
| Calibration (期待勝率 vs 実勝率) | 無い | シム評価で回収 |
| Noise robustness | 決定再生の反転率 (あり) | 継続 |
| Latency p50/p95 | **計測なし** | server の advice 計算時間をログへ (P7 と同時に) |
| Churn | 監査で集計 (あり) | 継続 |

## 5. リスクと未確認事項
- K 仮説探索のレイテンシ (未実測)。
- 価値較正の失敗履歴 (2026-07-27)。較正なしで葉評価を強めない。
- 自己対戦方策を相手モデルにすると、人間の行動分布とズレる (λ で混合し、実対戦ログで検証)。
- 外部システムの数値は未確認。
