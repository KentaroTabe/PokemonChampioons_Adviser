# Jev 調査メモ

調査日: 2026-09-22

## 要約

Jev は TypeSafe AI が提供する **System One model** で、文章を生成するチャットモデルではなく、与えられた状態（`state`）に対して、あらかじめ定義した選択・採点・真偽判定を高速に返す「判断モデル」である。出力を閉じた型に限定し、確率分布や信頼度をアプリケーション側の分岐に利用する。

この性質は、リアルタイム会話支援の次の箇所に合う。

- 今の発言へ合いの手を入れるべきか
- 合いの手が「ツッコミ」「共感」「同意」「励まし」「確認促進」のどれか
- 割り込む価値や発言の不確かさがどの程度か
- 複数の短い定型候補のどれを選ぶか

一方、自由文生成、精密な計算、複雑な推論、根拠を伴う事実訂正は Jev 単体の役割ではない。音声も直接入力できないので、音声認識でテキスト化してから渡す必要がある。

## 1. 基本概念

公式ドキュメントでは、Jev は共通の `state` に対して複数の型付き質問を評価する。質問は互いに独立して並列評価される。

| Primitive | 用途 | 主な返り値 |
|---|---|---|
| `Choice` | 閉じた候補から1つ選択 | `choice`, `probabilities`, `confidence` |
| `Score` | 順序付き基準で採点 | `score`, `probabilities`, `confidence` |
| `Noul` | 条件が真である確率 | `noul`（0〜1） |

API の基本形は次のとおり。

```http
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer $TYPESAFE_API_KEY
Content-Type: application/json
```

```json
{
  "state": {
    "utterance": "いや昨日は一睡もしてないけど元気だよ",
    "recent_context": ["徹夜で作業していた"],
    "seconds_since_last_interjection": 14
  },
  "model": "jev-latest",
  "questions": {
    "kind": {
      "type": "choice",
      "instructions": "発言直後に最も自然な反応種別を選ぶ",
      "criteria": {
        "none": "反応しないのが自然",
        "tsukkomi": "誇張、矛盾、ボケへの短いツッコミ",
        "empathy": "気持ちへの共感",
        "caution": "断定せず確認や注意を促す"
      }
    },
    "should_speak": {
      "type": "noul",
      "instructions": "今ここで短い合いの手を発すると会話体験が良くなる"
    }
  }
}
```

## 2. 現行モデルと提供条件

2026-09-22 時点の公式モデル一覧では、安定版は `jev-1.13.0`、`jev-latest` はその安定版を指す。公式記載の主な条件は以下。

- 入力: テキストのみ。画像・音声・動画は非対応
- コンテキスト: 1リクエスト64k token、`state` と最長質問の組み合わせは32k token
- 料金: 入力100万 token あたり USD 0.042、出力 token は無料
- レート上限: 250,000 token/秒、1,200 request/分（変更され得る）
- 主学習言語は英語。CJKを含む他言語も扱うが同等精度ではなく、実データ評価と信頼度ゲートが必要
- 顧客のリクエスト/レスポンスは学習に使わないと明記。エンタープライズ向けゼロデータ保持の詳細は別途契約・規約確認が必要

`jev-latest` は将来別バージョンへ移動する。実運用でしきい値を調整した後はバージョンID固定を検討する。

## 3. Jev が得意なこと

### 3.1 閉じた出力空間の高速判断

コードが許可した候補以外を返さない。自由文のJSON化に失敗する問題を避けられ、実行側が常に主導権を持つ。

### 3.2 Speculative fan-out

1回のAPI呼び出しに、反応種別、発話価値、事実リスク、感情、割り込み不快度などをまとめて渡せる。質問は並列評価され、アプリケーションが必要な結果だけを採用する。

### 3.3 不確かさをアプリケーションで扱える

`Choice` と `Score` は確率分布と `confidence` を返す。高信頼度なら自動発話、中程度なら穏当な候補だけ、低信頼度なら沈黙、というリスク別ゲートが作れる。`Noul` には `confidence` がないため、返された確率に用途別しきい値を設ける。

## 4. 制約と注意点

### 4.1 生成モデルではない

Jev 1.13 の公式 jaggedness 文書は、生成が必要なら生成モデルを使うよう明記している。本システムでは Jev に台詞を書かせず、コード内の短い承認済み候補から選ばせる。

### 4.2 事実訂正は別の証拠レイヤーが必要

Jev は「この主張は要確認に見えるか」という高速判断には使えるが、最新情報の検索や根拠生成を行わない。訂正内容を断定するには、信頼できるデータソースからの検索、出典確認、必要なら推論モデルが別途必要。根拠がないMVPでは「それ、念のため確認したほうがよさそうなのだ」のような確認促進に限定する。

### 4.3 日本語性能は要実測

日本語発話、口語、省略、方言、ボケ、皮肉は特に評価セットを作る必要がある。低信頼度時は発話しない方を既定にし、誤った割り込みより取りこぼしを優先する。

### 4.4 長大・無関係な履歴を送らない

Jev 1.13 は無関係な状態が増えると精度が落ちると公式に説明されている。本実装は直近最大3発話へ絞り、要約や計数はコード側で行う。

### 4.5 数値・時刻・論理整合性はコード側

クールダウン、1分あたり発話数、時刻比較、重複排除などはモデルへ質問せず、決定論的に実装する。

## 5. 本システムへの適用方針

1. 選択した物理マイクのみをキャプチャする。
2. VADで発話区間を切り、ローカルSTTで日本語テキストへ変換する。
3. 直近の短い文脈とともに、複数のJev質問を1リクエストで送る。
4. コードが信頼度、発話価値、クールダウン、頻度上限を合成して発話可否を決める。
5. 承認済みの短い候補から台詞を選ぶ。
6. VOICEVOX Engine のずんだもん音声で再生する。
7. 再生中はマイク入力を無視し、自己音声への再反応を防ぐ。

## 6. 評価すべき指標

- 誤割り込み率: 本来黙るべき発話に反応した割合
- 適合率: 反応種別が人手ラベルと一致した割合
- 発話率: ユーザー発話のうち合いの手を出した割合
- 反応遅延: 発話終了から音声再生開始までのp50/p95
- 自己反応率: ずんだもん音声を再認識して連鎖した割合（目標0）
- 話者混入率: 通話相手・スピーカー音をユーザー発話として処理した割合
- 日本語の信頼度校正: confidence帯ごとの実正解率
