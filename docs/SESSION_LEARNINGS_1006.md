## 2. 学び (技術)

1. **規則は予備にしかならない**。相性の規則 (ダメージ計算の対面行列) は 7 月の実測で乱択 0.25 に対し 0.29 で、学習モデルの 0.51 と差が大きい。
   新しいチームでも、未学習のモデルの推しの方が人の選出に近かった。規則を直すより、モデルがそのチームで使える状態を保つ運用の方が効く。
   規則を直すとき (自分側を攻撃全振りで評価していた、速度計画を見ない) は「予備の底上げ」と位置づける。
2. **少数標本の微調整は順位の情報を壊す**。単一チームの 1,000 戦 (半分は乱択の選出) を 200 epoch 微調整し、同じ収集の 2 割の検証 MSE が
   最小の epoch を採ると、120 通りの選出の順位が入れ替わる。検証 MSE は改善に見える (+25〜41%) が、順位の崩れを捉えない。選出モデルの
   良し悪しは**独立 fold の実測の勝率**でしか選べない (S7 の checkpoint 選択がそうしている)。検証の無い適応は使わない。
3. **仮説は実データで直す**。cheap の崩れ方を「平らになる」と予想したが、実データでは広がりが 1.3〜1.9 倍に増えて順位が入れ替わっていた。
   機構の予想が外れても結論 (検証の無い微調整は害) は変わらなかったが、直し方の候補 (崩れの門) は前提が外れて消えた。診断ツールを先に出して
   運用側に当ててもらう進め方が、判断を早くした。
4. **再利用と鮮度は引き換え**。分割の seed・使用率スナップショット・実在の構築のバンクを季節 (規制) で固定すると、参照の適応や fold の記録を
   run 間で再利用できる (数時間の節約)。代わりに環境の変化を取り込めないので、固定したスナップショットと最新の上位 30 種の重なり (順位の
   重みつき) を鮮度として測り、0.8 を切ったら警告する。固定し直しは新シーズンのデータが出たときに 1 回。
5. **制約は分けて書く**。「個体を残す」「型を保つ」「メガ形態を保つ」は別の制約で、まとめて「固定」と呼ぶと修理の候補が消える
   (現行チームに 2 枠の入替が 1 本も出なかった) か、黙って形態が変わる (ルチャブルの石が外れる)。生成・検査・修理・記録の全部で同じ区別を使う
   (メガ型と非メガ型は別候補、形態の変更は変種 F として記録、2 体の入替には数えない)。
6. **直せる誤りは捨てずに直す。ただし黙って大きく変えない**。型の常識規則の違反は、性格の下げる側・持ち物の予備・場の重複の技・4 つ未満の
   補充で直せるものが多い (240 種の代表型で誤り 15 種が全部直せた)。メガ石を外すのは想定フォルム・特性・役割まで変わるので自動修正の
   範囲を超える。直せなければ止めて理由を数える (`repair_blocked`、`form_changes`)。
7. **記録は層別できる形で残す**。実戦の勝率を「版」(指定 Package / 実際に読んだモデルの sha / 退避理由)、選出の ◎ の経路 (model / rule /
   model_untrained)、変種の種類 (A / B / F) と測ったかどうか (measured) で分けられるようにしておくと、次の run や接続テストの結果を
   混ぜずに読める。16 戦程度では勝率の差は出ないので、まずは一致率と局面の正誤で見る。
8. **ブラウザの表示の確認は隠れたタブで止まる**。requestAnimationFrame はタブが見えている間しか発火しない。表示時刻を測るなら
   document.hidden を見て即時に送り、サーバー側は到着した時点のファイルではなく助言 id の対戦に書く。

## 3. 学び (進め方)

- **運用側 (実データ) と実装側 (コード) の往復を表で回す**。運用側が「確認で見つかった点」と「判断待ち」を表にし、実装側が「対応」と
  「残り」を表で返す (PENDING §6〜§16)。1 回の往復で 5〜8 件が片づき、判断待ちが溜まらない。
- **純粋関数とテストで閉じる**。対戦を回せない環境でも、判断の部分を純粋関数に切り出してテストすれば (variants_for / select_variants /
  needs_cheap / resolve_pin / perm_stats)、run での通しの前に大半の誤りが取れる。run での通しは運用側の煙試験 (12 分) に任せる。
- **何を測っていないかを書く**。30 局面の誤り率は実戦の率ではない、16 戦では勝率の差は出ない、シムの 0.703 と実戦 0.533 は操縦者が
  違うので比べられない、など。数字の横に前提を書いておくと、次に読む人が誤って結論しない。
- **CI の既知の赤 4 件を名前で持つ**。この環境では showdown のデータ・使用率 DB・torch・gymnasium が無く、4 モジュールが必ず赤になる。
  名前を決めておけば、他の赤がすぐ分かる。
- **自分のテストの穴**。`assert A if False else True` のように常に真になる書き方を一度残した。テストが落ちることを確かめてから直す
  習慣に合わせる (運用側は、確認したときは「直す前のコードで落ちることを確認した」と書いている)。

## 4. 登場した仕組みの説明 (前提の知識なしで読めるように)

- **選出モデル**: 自分の 6 体・相手の 6 体・選ぶ 3 体の順 (120 通り) から勝率を予測する小さなニューラルネット。多くのチームのデータで
  学習した「汎用」を土台に、実際に使うチームの数千戦で微調整したものが「配布版」や「適応モデル」。見たことのないチームの選出までは
  汎化しないので、チームを替えたらそのチームのデータで寄せ直す必要がある。「分布内」とはそのチームのデータで学習済みという意味。
- **微調整と検証**: 汎用の重みを起点に少しずつ学習し直すこと。学習に使ったデータの一部を取り分けて誤差を見るのが検証 MSE だが、
  勝敗 0/1 の少数標本では、誤差が小さくなっても順位 (どの 3 体が良いか) が正しいとは限らない。実際に対戦させて勝率で選ぶ方が確か。
- **相手プールと層化分割**: 使用率データから合成した相手の構築 (と実戦で当たった構築) を系統にまとめ、探索 (SEARCH)・選出 (SELECTION)・
  封印 (HOLDOUT) の層に分ける。SEARCH はさらに fold に分け、適応の収集・評価・checkpoint の検証を別の fold で行う。HOLDOUT は run の
  最後まで触らない (封印) ので、採否の判定が探索に引きずられない。
- **seed と決定性**: 乱数の出発点。同じ入力と同じ seed なら同じプール・同じ分割になる。入力 (使用率のスナップショット) が変われば
  seed が同じでも分割は変わるので、季節で固定するなら seed とスナップショットの両方を記録する。
- **racing**: 複数の候補を同じ相手の列で少しずつ対戦させ、統計的に負けが確定した候補から落としていく測り方。S8a は候補 × 選出方策
  (規則 / 汎用) の腕で回し、腕の最善をそのチームの実力とする。
- **較正の標本**: 代理評価 (対戦なしの点) が実測とどれだけ合うかを見るために、上位でない並びも少し測る標本。上位だけ測ると代理の
  当たり外れが見えない。
- **型の常識規則 (lint)**: 性格が下げる側の攻撃技を持たない、持ち物と技が噛み合う、特性と同じ場の技を重ねない、技は 4 つ、といった
  人が見れば分かる誤りの検査。誤りは直せるなら直して残し、直せなければ落とす。
- **メガ形態**: メガ石を持つ個体はメガシンカ後の種族値・タイプ・特性で戦う。検査も評価もメガ後で見る。石を外すと別の型 (非メガ型)
  になるので、同じ種の別候補として扱う。
- **version 行 / advice_id / display 行**: 対戦ログに、どの版 (Package・モデルの sha・退避理由) が動いていたか、どの助言 (id と見ていた
  状態) を出し、いつ表示されたかを別々の行で残す仕組み。評価の版と実戦の版が同じかを後から確かめられる。
- **requestAnimationFrame**: ブラウザが次の描画の直前に呼ぶ関数の予約。描画が済んだ時刻を取るのに使うが、タブが隠れていると
  描画が止まるので呼ばれない。
- **季節の固定 (pin)**: 評価側で使っている META_PIN / POOL_PIN と同じ考え方で、ある時点の使用率スナップショットや seed を記録して
  以後も同じものを使うこと。鮮度の警告で、固定し直す時期を見逃さないようにする。
