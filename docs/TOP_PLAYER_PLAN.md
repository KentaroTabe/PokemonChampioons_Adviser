# 最上位プレイヤーに勝ち越すための実装計画

2026-07-19策定。ゴール: アドバイザーの提案通りに指せばマスター最上位帯で
勝ち越せる水準。

## 現状と差分の分析

**到達済み**: 状態抽出 (1試合=1ファイルのフロー再構成まで)、Lv50ダメージ計算、
1手読み期待値評価、4枠技モデル、型推定 (先後/ダメージ観測)、選出提案、
自分の型登録、手動種族確定。

**最上位との差** (対戦AI研究と上位勢の構築記事から):
- 最上位の意思決定は「毎ターンの全選択肢×相手の応手の予測」+「数ターン先の
  展開 (勝ち筋・詰め筋)」で行われる。現在の1手読み期待値では、
  **択 (同時手番の駆け引き)** と **サイクル戦の交代読み** と
  **終盤の詰み筋** が評価できない
- 対戦AI側の知見でも、人間エキスパート級に達した系は例外なく
  **先読み探索** (foul playのMCTS+ダメージロール群化、PokéChampの
  ミニマックス+相手モデル) を核にしている
- 認識誤りが1つでも残ると探索が深いほど誤った結論を強く支持してしまうため、
  **認識の最終防衛線としての手動修正**が前提条件になる

---

## Phase 1: 認識の信頼性 (前提条件・最優先)

### 1.1 状態の手動修正UI ★ユーザー指名
フロントエンドから全状態要素をその場で修正できるようにする。
- 対象: HP (実数/%)、ランク、状態異常、天候/フィールド/ターン数、設置技、壁、
  持ち物、特性、残数、メガ済みフラグ (種族は実装済みのプルダウンを拡張)
- 実装: 各表示要素をクリック→インライン編集→ `set_state` イベントで
  サーバーに反映 (set_species と同型)。修正は `manual_fix` イベントとして
  対戦ログに記録 (何を・どの値から・どの値へ)
- 工数: 中 (1セッション)

### 1.2 修正ログの分析ツール
`tools/analyze_corrections.py`: 対戦ログの manual_fix を集計し、
「どの要素が・どのシーンで・どれくらい直されたか」の誤認識ランキングを出す。
→ 以後の認識改善はこのランキング駆動で行う (推測ではなくデータで直す)。
- 工数: 小

### 1.3 低確信値の可視化
2回連続確認が取れていない値・推定値 (型/種族/技) をUI上で「?」付き表示し、
ユーザーが修正すべき箇所を一目で分かるようにする。
- 工数: 小

## Phase 2: 意思決定エンジンの深化 (勝率への寄与が最大)

### 2.1 択 (同時手番) のゲーム理論的処理 ★最重要
現在は「相手の最大脅威に対する期待値」のみ。上位帯は択の質で決まる。
- 自分の行動×相手の行動 (技+交代先) の**利得行列**を作り、
  (a) 最悪ケース保証値 (ミニマックス) と (b) 使用率重み期待値の両方を提示
- 「負け筋のある択」(その行動を choose して相手が最善なら負けに近づく) に
  ⚠を付け、リスク許容度で並べ替えられるようにする
- 相手の応手予測に型推定 (実装済み) と使用率を利用
- 工数: 中〜大

### 2.2 2手先読み探索
1手読み→2手読み (自分の行動→相手の応手→次ターンの盤面評価)。
foul play の知見に倣い**ダメージロールの群化** (16乱数を3-4グループに集約) で
組合せ爆発を抑える。盤面評価関数は現在のスコアリングを流用。
- 工数: 大。2.1の行列が土台になる

### 2.3 詰み筋・勝ち筋の判定
残存メンバー同士の**1v1マッチアップ行列** (誰が誰に勝つか) を毎ターン更新し、
- 「相手の残り全員に勝てる自分のポケモン」= 勝ち筋 (これを温存/通す提案)
- 相手側の同判定 = 負け筋 (これを先に処理する提案)
- 終盤 (2v2以下) は全展開の完全読みで「この順で指せば勝ち」を提示
上位勢の「勝ち筋を意識した数ターン先のプレイング」に相当する。
- 工数: 中。サイクル構築 (クッション経由の有利対面作り) への対抗にも必須

### 2.4 サイクル戦への対応 (交代読み)
相手のベンチ (判明分+推測) への交代も相手の行動空間に含める (2.1の行列に列を
追加するだけ)。とんぼ/ボルチェンのテンポ、ステロ込みの交代コスト、
クッション (受け出し) 誘発の予測を評価に入れる。
- 工数: 中 (2.1に内包)

### 2.5 資源管理
PP (プレッシャー込み)、天候/フィールドの残りターン、壁ターン、
メガシンカ権 (切るタイミングの期待値差を毎ターン評価)、残り時間
(COMMAND秒読み取り済み→時間切れ間際は計算を打ち切り即答)。
- 工数: 小〜中 (分散して実装可能)

## Phase 3: 情報モデルの精緻化

### 3.1 型推定の観測拡張 (実装済み基盤の強化)
- こだわり系判定: 同一技の連続使用+交代パターン
- きあいのタスキ/がんじょう: 高乱数域で残HP1の観測
- 回復量の実数観測 (オボン25%/たべのこし6%) からの最大HP逆算
- 素早さの上下界を二分探索的に狭める (毎ターンの先後で範囲更新し表示)
- 工数: 中

### 3.2 構築テンプレートマッチング
チームプレビューの6体構成を、pokedb公式オープンデータの上位構築と照合。
一致度が高ければ**残りメンバーの型・技・持ち物を構築記事の記載で補完**する
(上位帯はテンプレ/レンタル構築の使用率が高く、6体一致なら型まで確定に近い)。
- 工数: 中。選出提案の精度にも直結

### 3.3 再戦キャッシュ
プレイヤー名 (対戦開始画面から取得済み) ごとに過去の判明情報 (型・技・選出
傾向) を保存し、再戦時に事前分布として読み込む。
- 工数: 小

## Phase 4: RLとの融合

- 4.1 RL方策を2.1/2.2の**相手応手予測の事前分布**・葉ノードの価値関数として
  利用 (AlphaZero型のハイブリッド)。ベンチマーク勝率0.57→の学習が続くほど
  探索の質が上がる構造にする
- 4.2 対戦ログからの較正: アドバイス採用/不採用×勝敗を集計し、
  評価関数の重み (交代ペナルティ等) をデータで調整
- 工数: 大 (Phase 2完了後)

## Phase 5: 実運用UX

- 択の根拠の言語化 (「相手がじしんなら〜、交代なら〜」の分岐表示)
- アドバイス履歴と結果の振り返り画面 (負け試合のターン別分析)
- 工数: 小〜中

## 実施順序 (推奨)

| 順 | 項目 | 理由 |
|---|---|---|
| 1 | 1.1 手動修正UI + 1.2 修正ログ分析 | 全機能の前提。誤認識の定量化が以後の羅針盤 |
| 2 | 2.1 択の利得行列 | 勝率寄与が最大。2.2-2.4の土台 |
| 3 | 2.3 詰み筋判定 | 実装が独立していて効果が分かりやすい |
| 4 | 3.2 構築マッチング + 3.1 観測拡張 | 行列の入力精度を上げる |
| 5 | 2.2 2手読み + 2.5 資源管理 | 探索の深化 |
| 6 | 3.3 再戦 / 4.x RL融合 / 5.x UX | 積み上げ |
