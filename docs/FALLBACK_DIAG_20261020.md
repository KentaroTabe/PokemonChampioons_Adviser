## 1. 結論

- 5 決定の退避の原因は 1 つ。**相手のメタモンが かわりもの で こちらの個体に へんしん した状態を、状態も助言エンジンも扱っていない**。
  相手の場の個体は「ノーマルタイプのメタモン (技 へんしん だけ)」のままで、使用率の技 へんしん (効果の表に無い変化技) が応手に入る。
  記録の退避理由の 2 種類 (へんしん 9 行、未評価の区間 11 行) は同じ原因で、分かれたのは へんしん の重みの違いだけ (§3)。
- 未評価の区間で退避した 3 決定の未評価の応手は 3 件とも へんしん だけ。ほかの技の未評価は無い。
- 合成入力 (相手の場の個体を「コピー元のこちらの個体の写し、HP は相手のまま」に置き換える) では、5 決定とも退避せず transition で評価できた
  (へんしん が関わる advice 行 20 行も全部)。この対戦に限れば、退避は 5/13 → 0/13 の見込み。
- ただし最小の対応にも「コピー元 = へんしん した時点のこちらの場の個体」を覚える状態の欄が要る。今の場の個体で代用すると、
  こちらが交代・ひんしした後 (ターン 4) に別の個体の写しになる (退避はしないが入力が誤る)。

## 3. 何が要るか

### (a) へんしん

- 退避の判定箇所: `advisor/transition.py` の変化技の解決 (効果の表に無い変化技は unsupported "effect_unmodeled")、
  `advisor/scoring_transition.py` `_score_core` (相手の応手の未対応の効果: 推定技なら未評価に回し、判明技なら opp_unsupported で退避)、
  `estimated_moves` (推定技 = pool の重み < 100)。
- ターン 2 だけ opp_unsupported になったのは、判明技が 0 個のとき `engine.opponent_move_pool` の へんしん の重みが 100% × (0.5 + 0.5 × 4/4) = 100 になり、
  `estimated_moves` が「重み 100 = 判明技」とみなしたため。判明技が 1 つ以上あると重みは 87.5 / 75 で推定技になり、未評価に回る。
  判定を「判明技の集合に入っているか」だけにしても、この局面は ε = 0.9 で未評価の区間で退避する (§4 as_est)。退避の数は変わらず、理由の名前が揃うだけ。
- 合成入力 (相手の場の個体の置き換え) を入れると、相手の技は写した 4 つ (判明技、重み 100) になり へんしん が応手から消える。ε = 0 で区間の判定そのものが無くなり、
  5 決定とも transition が順位を返した。

### (b) 未評価の区間で順位が決まらない

| 決定 | 未評価の応手 | ε | 未評価の応手を除いた q (参考、設計で不採用の扱い) | 区間が重ならない ε の上限 |
|---|---|---|---|---|
| 0166 | へんしん | 0.274 | ふいうち 0.160、アイアンヘッド 0.032、ドゲザン 0.021 | 0.061 |
| 0202 | へんしん | 0.304 | のしかかり 1.0、じしん 1.0 (同点)、はねやすめ 0.139 | 0 (同点なので どの ε でも決まらない) |
| 0206 | へんしん | 0.111 | のしかかり 1.0、じしん 1.0 (同点)、はねやすめ 0.142 | 0 |

- 3 件とも未評価の応手は へんしん だけで、(a) で消える。区間の規則を変える必要はこの 5 決定には無い。
- 0202 / 0206 の q = 1.0 の同点は「ノーマルのメタモン (あくのはどう) は怖くない」という誤った入力から出た値で、写しで評価し直すと同点は消える
  (0202: のしかかり −0.003、はねやすめ −0.065 ほか)。別の観察として、2 つ以上の候補が V の上限 (確実な勝ち) で並ぶと ε > 0 では必ず退避する
  性質がある。今回の 5 決定の修正には関係しないので、ほかのログで出たときに扱う (案に入れない)。

## 5. 必要な修正の最小案 (案。決定はレビュー・開発者)

### 案 A: へんしん した相手を「こちらの個体の写し」として入力に入れる

- 対象の効果: かわりもの (メタモン) の へんしん と、技 へんしん を使ったのを見た場合だけ。ほかの写す効果 (スキルスワップ 等) は対象外。
- 写す: 種族 (メガ形態のまま。相手はメガシンカを使えない扱い)・タイプ・特性・技 4 つ (判明技、重み 100。それまでの判明技は消す)・
  能力ランク (へんしん した時点の値。その後の変化は観測どおり)。実数値は本来こちらの個体の実数値 (HP を除く) で、合成入力では
  写した種族の使用率の配分で代用した。
- 残す: HP (割合と最大 HP はメタモンのもの)・状態異常・持ち物 (メタモンのもの。観測が無ければメタモンの使用率)。
- コピー元: へんしん した時点のこちらの場の個体。状態に「写しの元 (種族と能力ランク)」の欄を足し、メタモンが引っ込んだら消す。
  記録が無いとき (かわりもの の表示を読めなかった、ターン 1〜2 のように) は、メタモンが場に出た時点のこちらの場の個体を使う
  (かわりもの の採用 99.5% を前提にする閾値は設定に置く)。
- 置く場所の選択肢 (選び方で既存の挙動が変わる):
  - A1 状態 (画面認識の側) で写しにする: legacy も変わる (§4 で 4/5 決定の第一候補が変わる)。
  - A2 エンジンの相手の個体の作成 (`engine.py` の `build_mon_view(opp_p, …)` の前) で置き換える: 両方式とも変わる。状態の記録は元のまま。
  - A3 transition の入力 (`scoring_transition.build_inputs`) だけで置き換える: legacy は変わらないが、両方式が別の相手を見ることになる。
- 記録: advice 行の state に写しの欄を足す (版 2 の読み取り互換は壊さない)。再生が同じ入力を作れるようにする。

### 案 B (任意): 推定技の判定を重みでなく判明技の集合で行う

- `estimated_moves` が使用率 100% の技 (判明技 0 個のとき重み 100) を判明技とみなす問題。直しても今回の退避の数は変わらない (理由の名前が揃うだけ)。
  ほかの局面では「退避」が「未評価の区間で続行」に変わり得るので既存の挙動の変更になる。

## 6. 残す退避

- かわりもの でないメタモン (じゅうなん 0.5%) が技 へんしん を選び得る局面: へんしん を未評価の応手に残す (解決できないため)。
- 写しの元が分からない局面 (メタモンが出た時点のこちらの場の個体が状態に無い 等): 退避を残す。
- 区間の規則 (§3 (b)) は変えない。受入基準・分母も変えない。
