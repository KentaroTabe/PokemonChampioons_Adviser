# 1 試合 1 回の資源 (メガシンカ) の推定: 設計

作成: 2026-09-11。ユーザー指摘「シミュレータの相手がチームプレビューからメガ先を推測しないのは致命的。
ダイマックス/テラスタルのような 1 試合 1 回の手段が増えたとき試合の流れを予想できない。
少なくとも選出提案の学習では必須、構築提案のシミュレータ相手にも必要」への対応。

## 1. 現状 (対応前) の欠落

| 部品 | 相手のメガ先 | 自分のメガ先 |
|---|---|---|
| 選出モデル v1 (`agent/selection_model`) | 見ない (種族埋め込みのみ) | 見ない (石の有無を知らない) |
| 行動方策の観測 (`agent/encoders`) | 「相手が既にメガシンカ済みか」だけ | 「自分がメガシンカ可能か」だけ |
| 助言の探索 (`advisor/search`) | 相手の行動に「メガシンカ」の分岐が無い | 助言側の注記のみ |
| 発見的な選出 (`advisor/selection`) | 相手候補は素の姿だけ | 石持ちはメガ後で評価 (対応済み) |
| 構築の相手 (RL 方策 + 選出モデル) | 上記と同じ盲点 | 同じ |

## 2. 共通の推定器: `advisor/gimmick.py`

- 相手の持ち物は見えないので、**種族ごとの「メガ石を持つ確率」を使用率 DB の石の使用率から事前分布**として持つ
  (`stone_prior`: {メガ後 id: p}。X/Y は石ごとの使用率で按分。石を持てるが使用率が無い種は `GIMMICK_DEFAULT_STONE_PRIOR`)。
- 判明情報で上書き (`expected_mega`): 持ち物が石と判明 → その姿 1.0、石以外と判明 → 0、既にメガ後 → 0、
  陣営のメガ権利が消費済み → 0。
- 自分側は持ち物が分かるので確定。
- `mega_view` (MonView をメガ後の姿に)、`mixture_base_stats` (期待種族値)、`team_mega_probs` (6 体分)。
- 将来のダイマックス/テラスタル等は同じ枠 (種類ごとの事前分布 + 判明情報 + 権利の消費) で足す。

## 3. 各部品への組み込み

1. **助言の探索** (`advisor/search`): 相手の技の候補を「メガシンカあり / なし」に分岐 (`opp_mega_split`、
   p ≥ `SEARCH_OPP_MEGA_MIN_PROB`)。分岐では技の解決前にメガ後の姿 (種族値/タイプ/特性) に変え、権利を消費。
   交代すると新しい場のポケモンの分は不明。engine は相手の場のポケモンの見込みを SimSide に渡し、注記
   「相手もメガシンカ未使用: メガリザードンY 60% の見込み」を出す。
2. **発見的な選出** (`advisor/selection`): 相手候補にメガ後の姿を確率で混ぜる (`_with_mega_candidates`)。
3. **選出モデル v3** (`agent/selection_features_v3`): 自分の石持ちはメガ後の埋め込み、相手は事前分布で混ぜた埋め込み、
   スカラー 6 (選出 3 体の石フラグ、控えの石持ち数、相手の P(石) 平均/最大)。埋め込みにメガ後の姿を追加
   (`tools/species_embedding`: 基本種の型にメガ後の種族値/タイプ/特性)。`train_selection --features v3`。
   v1 と同じ門 (未知チーム検証の MSE 改善、対応比較の順位精度) で比較し、劣らなければ汎用モデルを v3 に切り替える
   (構築の相手の選出 `apply_model_teampreview` もそれを使う)。
4. **行動方策の観測 v8** (`agent/encoders`、末尾追記 16 次元): 相手の場の P(メガ残り) と期待種族値の差、相手控え 2 体の P、
   自分の場/控えの石フラグ、権利の消費 (自分/相手)、陣営の残りメガ脅威。既定の学習は v6 (388) のままで、
   `TRAIN_OBS=v8` で 436 次元。既存の 388 チェックポイントは `train/migrate_obs.py` で入力層をゼロ拡張して
   (挙動は同一のまま) 続きから学習できる。**切替 (学習ループの再起動) はユーザーの承認後**。

## 4. 限界と検証

- 事前分布は「石を持つ確率」であり、「その試合でメガシンカする確率」ではない (3 体選出と判断に依存)。
  観測・特徴量ではそのまま渡し、学習側に任せる。
- 相手の手持ちのうちプレビューで見える 6 体の情報は poke-env の `opponent_team` に依存する
  (BSS はプレビューで 6 体が見える)。
- 効果の検証: 選出 v3 はオフラインの門 + 対戦 (20,000 戦の実測)、方策 v8 は学習曲線とベンチ、構築の相手は
  rule 系 run の再測定で見る。
