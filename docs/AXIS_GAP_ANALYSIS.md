# 測定軸の乖離解析 (vs_agents vs ベンチマーク)

開始: 2026-08-17 深夜。観測v7の棄却 (RL_V7_SET_ENCODER_DESIGN.md) を受けた
事前登録済みの次レバー「測定軸の見直し」の実施記録。

> **⚠ 2026-08-18 追記: §7 で根本原因が特定され、本文の所見の一部は
> 訂正されている。** vs_agents 軸は導入時から「自チーム1個を全戦使い回す」
> 欠陥を持ち、agents軸を使った水準値 (§2-2 の 0.405 / 0.452 等) は
> 1走行分のチームドロー運を含む。§1〜§4 は調査過程の記録として原文の
> まま残す。確定した結論は §7 を正とする。

**動機**: 日次定点で vs_agents (対エージェント軸) が4日で +0.15 上昇する間、
ベンチマーク軸 (対ヒューリスティクス) は横ばいだった。2つの軸が別の動きを
するなら、どちらかが実力を映していない。

## 1. 方法

すべて current (balance) を測定対象、相手列は `--opp-seed 20260730` で固定、
選出は両陣営とも相性ベース。8/17 23時台〜8/18 0時台に実施。

- **分解**: vs_agents の3性格巡回を単一性格に絞る (`evaluate --agents-style`、
  この解析のために追加。既定は従来どおり巡回で測定基準は不変)
- **holdout**: ベンチマークの自チームを学習に使っていない構築だけにする
  (`evaluate --own-teams holdout`。実装済みだったがCLI未配線だったのを配線)
- **参照の同一性**: _best 3本の md5 を確認

## 2. 結果

### 2-1. 測定の信頼性: 評価の並列実行は水準を歪める

同一測定 (current vs balance_best, 3000戦, 同一シード) の比較:

| 実行条件 | 勝率 |
|---|---|
| 3〜4本の評価と並列 | 0.234 |
| **単独 (逐次)** | **0.405** |

差 +0.17 ≒ 13SE。約30分の学習ドリフトでは説明できず、並列実行の負荷が
測定を歪めたと判断する (機構は未確認)。一方、2本並列は軽微:
合算 0.480 (2本並列) vs 0.452 (単独) で差 1.5SE 程度。
**8/17の本判定 (10,000戦×2本同時) はペア設計で両アームが同条件のため、
差 (-0.130) は有効。** 日次定点は元々逐次実行のため汚染されていない。

**以後の規律: 水準の測定は単独で走らせる。A/B比較はペア同時のみ。
3本以上の並列評価は禁止。**

### 2-2. 水準 (信頼できる逐次測定のみ)

| 測定 | 8/15 定点 | 8/17-18 (本解析) |
|---|---|---|
| current vs ベンチ (学習と同じ上位60構築) | 0.584 (1,500) | 0.605 (10,000)* |
| current vs ベンチ (**未学習構築 holdout**) | — | **0.520** (3,000) |
| current vs **balance_best 頭打ち** | — | **0.405** (3,000) |
| current vs agents 合算 (3性格巡回) | 0.618 (1,500) | **0.452** (3,000) |

*本判定のベースアーム (2本並列ペア)。参考: 並列2本のoffense/cycle分解は
0.472 / 0.428 (水準としては参考値)。

参照 (_best) は 8/11以降すべて同一 md5 (balance=01ee91a0 8/2生成 /
offense=ec7b9e55 8/3 / cycle=6990dce0 7/30)。auto_tune は 7/24 に定着後
無変更で、報酬設定の交絡はない。

## 3. 所見

### A. current は配布中の _best に頭打ちで明確に負けている

vs balance_best = **0.405 ± 0.018**。ベンチ軸では current 0.584 vs
_best+モデル選出 0.590 と互角に見えるが、直接対戦では 2週間前の _best が
current を6割方倒す。**_best昇格が2週間止まっているのは正しい判断だった**
(現行の慎重な昇格規則が配布品質を守った)。同時に、ベンチ軸は
「区別できないほど感度が低い」ことの実証でもある。

### B. vs_agents 軸は2日で -0.166 の実落下 (乖離の正体は軸の脆さ)

0.618 (8/15) → 0.452 (8/18)、参照・シード・実行条件は同一。ベンチ軸が
横ばいの間にこれだけ動く軸は、単独では進捗指標にならない。
落下期間は使用率DB復旧 (8/16 19:41、学習チーム分布が実質14種→109種へ
正常化) と重なる。仮説 (未確認): 汚染期間の14種ミラー学習が、ランク上位
構築の中核種と一致していたため対エージェント軸の見かけを押し上げ、
正常化とともに剥落した。この仮説が正しければ **8/13〜15の「上昇」は
汚染の産物**で、0.45前後が正直な水準となる。
検証は過去チェックポイントが残っていないため遡れない (→ 所見D)。

### C. ベンチ値は「見慣れたチーム」で約 +0.08 水増しされている

holdout (未学習構築) では 0.520。配布時はユーザーの任意チームを操縦する
ため、実運用の下限はベンチ値 0.60 ではなく 0.52 に近い。
ただし holdout はレート61位以下の構築であり、チーム自体の質が低い交絡を
含む (操縦の不慣れと分離するには同一チーム群での比較が必要)。

### D. 構造問題: 相手プールが「直近2時間」しか覚えていない

相手プール20件のうち15件は測定時点から2時間以内の自己スナップショット
(+7/24の旧stall系5件)。世代管理が「性格ごと最新5件」のため、
(1) 直近の自分としか戦わず古い戦略族への対応を忘れる (忘却→非推移:
所見Aの機構候補)、(2) 過去時点のcurrentが残らず、8/15の 0.618 を
再現・検証できない。

## 4. 改善案 (事前登録ドラフト)

### P1 (本命・学習): 相手プールに歴史的アンカーを常駐させる

_best 3本 (+今後は週1の間隔アンカー) をプール抽選に固定確率で混ぜる。
狙いは忘却の抑制と、頭打ちで負けている相手からの直接学習。

- 変更: opponent_pool の抽選にアンカー枠 (例: 25%) を追加
- **主要指標 (事前登録)**: head-to-head vs 3_best (各3,000戦・逐次) の平均。
  ベースライン 0.43 (0.405 / ~0.47 / ~0.43)
- **採用**: 7日で平均 +0.10 以上、かつベンチ軸 (10,000戦) が -0.02 を
  超えて悪化しないこと。判定は two_prop_verdict δ=0.02
- 判定不能/棄却時: プール多様化は撤回し、探索エキスパート混入率の
  引き上げを次候補にする

### P2 (測定): 軸の再編成と保持ポリシー

1. 日次定点に **head-to-head vs balance_best (1,000戦・逐次)** を追加
   (現状の合算 vs_agents は感度が高すぎ、ベンチは低すぎる。中間の
   直接対戦を主指標にする)
2. holdout ベンチを週次で測る (配布実力の下限の監視)
3. **週1でcurrentのスナップショットを保存** (アンカー兼、過去時点の再測用)
4. 評価の並列規律 (§2-1) を運用ルール化

### P3 (観察): 正常分布での収束を見る

vs_agents 合算の今後の定点が 0.45 前後で安定するなら所見Bの仮説
(上昇=汚染の産物) と整合。再上昇するなら別の機構を探す。

## 5. 実施記録 (2026-08-18)

P1〜P3 を実装した。

- **P1**: `opponent_pool.py` に `EPSILON_ANCHOR=0.25` を追加。アンカー
  (_best 3本 + `checkpoints/anchors/` の週次スナップショット) から一様抽選。
  枠は selfplay プール分 (0.45→0.20) から捻出。次の学習サイクルから有効。
  事前登録は training_changes.json 2026-08-18 01:25 のエントリを正とする
- **P2**: 日次定点 (`tools/track_progress.py`) に h2h_balance_best (1,000戦)
  を追加、holdout_benchmark (3,000戦) を月曜のみ追加、週次アンカー保存
  (`save_weekly_anchors`、性格ごと4本保持) を組み込み。定点自体を launchd
  (com.championsadviser.track-progress.plist、毎日21:50) で恒久化。
  並列規律は evaluate.py の docstring に明記
- **P3**: 追加コードなし (既存の vs_agents 定点の観察を継続)。
  予測: 汚染仮説が正しければ 0.45 前後で安定する
- 回帰テスト: `tests/test_anchor_pool.py` (抽選境界 / フォールバック /
  アンカー枠の規模 / 週次保存の間隔と保持数)

## 6. 本解析で追加した測定手段

- `evaluate --agents-style balance|offense|cycle`: agents軸の単一性格分解
- `evaluate --own-teams holdout`: 未学習構築での過学習検証
  (既定値はどちらも従来動作のままで、既存の測定基準・保存経路は不変。
  holdout測定は last_eval への保存対象から除外し昇格判定を汚さない)

## 7. 追記 (2026-08-18 深夜): 根本原因の特定と所見の訂正

h2h の再測が 0.405 / 0.565 と振れたため、**ネットを凍結して測定だけを
5回繰り返す**切り分けを行った結果、同一重み・同一シード・逐次実行でも
0.373〜0.617 に散った (SD 0.11 ≒ 二項ノイズの8倍)。方策の劣化カウンタは
ほぼゼロで、走行間の平均ターン数が25%違うことから、**vs_agents 軸が
導入時 (8/10) から「自チーム = 生成チーム1個を全戦使い回し」の旧経路に
落ちていた**ことを特定した。詳細は
[incidents/reports/2026-08-10-agents-axis-single-team-draw.md](incidents/reports/2026-08-10-agents-axis-single-team-draw.md)。
同日、agents軸を benchmark と同じ毎戦引き直し (両陣営とも上位60構築) に
修正し、凍結ネット同士の再測が二項ノイズの範囲で一致することを確認した。

### 所見の訂正

| 本文の所見 | 訂正後 |
|---|---|
| A: current は _best に頭打ち 0.405 で負けている | **撤回** (1チームのドロー付き・非対称条件の測定だった)。修正後の再測で再判定 |

| §2-1: 3本以上の並列評価が水準を歪める | **未確認に格下げ** (根拠の 0.234/0.405 差はチームドローの交絡)。逐次規律は予防措置として維持 |

### P1 事前登録への影響

ベースライン 0.43 は無効な測定に基づくため**再登録が必要**。修正後の
h2h (毎戦引き直し・対称条件) で基準を取り直し、8/25 の判定は新基準に
対して行う (判定手順の「3時間以上空けて2回測定し平均」は維持)。
EMA は方策振動の証拠が消えたため必須ではなくなったが、真のドリフトも
平滑化する無害な観察手段として維持する。
