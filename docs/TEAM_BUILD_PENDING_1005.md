### 2.3 テーマのエース選出率

### 2.7 昇格の定義

- registry の Package 12 件のうち 11 件は最終検証が 600 戦 (medium の上限)。100 戦は rule_0909 の 1 件だけ。

- 注意: 軽い適応モデルは従来の相手との対戦で作ったもの。rl の相手で適応し直した場合の値ではない。

帰結: 「探索の並びは現行チームに届かない」という 1002d・1003 の結論は、従来の相手 (heuristic) に対してのもの。現行チームは
過去の測定 (全部が従来の相手) を勝ち残ってきた並びなので、その相手に合った並びが残っている可能性がある。次の run を rl で測れば、
同じ条件 (rl で適応、600 戦) で確かめられる。相手の操縦を 1 種類に固定すると同じことが rl でも起きうるので、
操縦を混ぜる (対戦ごとに heuristic と rl を切り替える) 案を次の検討に挙げる。

## 4. 確認で見つかった点 (実装側への依頼)

1. **引き金の入力**: `triggers.gather` が読む実戦の勝率と戦数が、条件の違う 1 戦分になっている (§2.8)。同じ 6 体の実戦を直接数える経路が要る。
   実験 13 の既定の実戦勝率も同じファイルを読む (今回は 0.412 を引数で渡した)。
2. **一致率の測り方**: mixed のときの `s02_env_match.json` は、プールに入れた対戦そのもので測っている (§2.1)。
3. **較正の標本**: 3 変種で測っている。点の幅は広がらない (§2.4)。
4. **set_lint の例外の漏れ**: 登録チームのブリジュラス (ずぶとい + ドラゴンテール) が「性格と技」の誤りになる。効果が目的の技として
   ドラゴンテール / ともえなげ / ほっぺすりすり を例外に足す (10/5 に渡した定義の漏れ)。
5. **set_lint の副作用**: 煙試験では生成の途中で 644 型を落とし (代表型 167 を含む)、役割の型が作れず sweeper_setup に代えた核が複数出た。
   最終の生成型の誤りは 0 / 207、技が 4 つ未満の型は 0 で、目標は満たしている。落とした型の内訳を一度確認したい。
6. **種の集中**: 煙試験でもカイリュー 92%、ブリジュラス 72%。上限 50% は効いていない。
7. **記事の形式の判定**: 行単位なので、1 行にシングルとダブルの記事が両方ある行はまとめてダブルになる。
8. **段ごとの所要**: `review_run` に stage_durations は無い (計画書の記述と食い違う)。
