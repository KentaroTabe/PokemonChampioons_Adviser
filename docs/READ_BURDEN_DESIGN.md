# 「読みを減らせる構築」を学習環境に入れるべきかの分析

作成: 2026-08-04。定説「すべての読みを当てることはできないから、読みを
減らせる構築が良い」の本システムへの導入分析。

## 1. 定説の分解

この定説は2つの独立した主張を含む。

- **(a) 分散の主張**: 五分の読み合い (択) は当たり外れが運になる。択の回数が
  多い構築は、同じ実力でも勝率の分散が大きく、読みの的中率が5割を超えない
  限り期待値も上がらない。択を踏まずに勝ち筋へ行ける構築は再現性が高い。
- **(b) 認知負荷の主張**: 読みは人間にとって疲れる。千日手に見える局面でも
  「相手が行動を変えるパターン」を毎ターン予測し続ける必要があり、
  この負荷は終盤の執行ミス (読み放棄・雑な選択) として勝率に跳ね返る。

## 2. 本システムの層別の当てはまり

| 層 | (a) 分散 | (b) 認知負荷 |
|---|---|---|
| 操縦AI (RL方策) | 当てはまる (相手モデルの不確実性として) | **当てはまらない** (毎ターン全力で計算し、疲れない) |
| アドバイザー経由の人間 | 当てはまる | **一部残る** (アドバイスの実行判断・アドバイザーの読みも完璧ではない) |
| 構築推薦 (最終消費者=人間) | 当てはまる | **強く当てはまる** (人間が生で使う場面が本命) |

重要な非対称性: **ボットは (b) を持たない**。認知負荷の要素をボットの学習に
入れる理由はない。一方で構築推薦の最終消費者は人間なので、構築評価には
(a)(b) 両方の価値がある。なお、本システムのアドバイザー自体が人間の (b) を
肩代わりする装置であることにも注意 (択評価の自動計算 = 読みの外部化)。

## 3. 結論: どこに入れ、どこに入れないか

### 入れない: RL報酬 (操縦の学習)

- ベンチ相手 (ヒューリスティクス/自己対戦プール) は**読みを外してこない**。
  リスク回避 (保証値重視) は静的な相手に対して期待値を下げるだけで、
  ベンチ勝率はほぼ確実に悪化する (探索ハイブリッドの実測 0.56→0.33 が
  「保証値寄りの意思決定は静的相手に弱い」の傍証)。
- 報酬レバーは ko 採用でクローズ済み。再開するなら CVaR 系リスク鋭敏RLの
  事前登録A/Bが必要で、コスト大・期待効果小 (負の見込み)。

### 既に部分導入済み: 推論時の意思決定

- 択評価は**期待値と保証値 (最悪ケース) を両方計算**しており、
  `decide(by="recommended")` は両者のブレンド。
- 選出の均衡解 (predict_maximin) は「読みに依存しない選出」そのもの。
  ベンチ (読んでこない相手) では argmax と同等と実測済みで、
  **対人用として保持** — 定説の (a) をそのまま実装した形。

### 入れる価値がある (本命): 構築評価の「読み負荷」指標

構築の進化探索と診断に、勝率と独立した**読み負荷の測定**を加える。

## 4. 仕組みの具体案

### 指標の定義: 「重い択」カウント

1ターンの行動×相手応手の利得行列 (既存の択評価が計算している) から:

```
重い択 := 最善行動の (期待値 − 保証値) > θ となるターン   (θ=0.15目安)
読み負荷(チーム) := 1戦あたりの重い択の平均回数
```

- 「期待値は高いが読みを外すと大損」な局面の頻度 = 定説の「読み」の
  発生回数の操作的定義。
- 補助指標: 択の利得行列の混合均衡エントロピー (0=読み不要の一本道)。

### 実装場所 (段階導入)

- **Phase A (測定のみ・低コスト)**: 進化探索の評価対戦で数ターンおきに
  択評価をサンプリングし、個体ごとの読み負荷を記録。パーティ診断にも
  「このチームは1戦平均N回の重い択」の行を追加。実対戦ログからの事後計算も可
  (search は局面再現で回せる)。
- **Phase B (相関確認)**: 読み負荷と (i) 実戦勝率、(ii) 評価のシード間分散の
  相関を測る。負荷が高いチームほど分散が大きい/実戦勝率が低い、が
  確認できたら次へ。
- **Phase C (選択圧・事前登録A/B)**: 進化探索の適応度をタイブレーク化
  「勝率が同等 (±SE) なら読み負荷が低い個体を残す」。勝率主目的は
  変えない (読み負荷を主目的に混ぜると弱いが楽なチームへ退化する)。

### 入れない実装 (検討して却下)

- 報酬への分散ペナルティ / CVaR-PPO: §3の通り。
- 千日手対策としてのループ検出報酬: ボットは千日手で疲れないし、
  実際のBSSはPP/天候ターンで自然に打開される。優先度なし。

## 5. 期待効果の見積り (正直な数字)

| 対象 | 期待効果 | 根拠 |
|---|---|---|
| ボットのベンチ勝率 | **±0.01以内 (ほぼゼロ)** | 相手が読みを外さないため保証値重視の利得なし |
| 評価の分散 (再現性) | シード間分散の低減が測定可能な程度 | 択の運が分散の一部を占める (寄与率は Phase B で実測) |
| 人間の実戦勝率 | **粗い見積りで +数%** | 1戦3回の重い択 × gap 0.2 × 読み的中率5割と仮定すると、択由来の期待損失は勝率換算 ~0.3 相当。構築で択回数を半減できれば その半分が浮く。ただし仮定依存が強く、Phase B の実測なしに確定しない |
| 構築推薦の説得力 | 定性的に大 | 「勝率68%・重い択1.2回/戦」は「勝率70%・重い択4回/戦」より人間には使いやすい、を数字で示せる |

## 6. 推奨

**Phase A から始める** (測定のみ、選択圧なし)。理由:
1. ボット側の指標 (ベンチ) には効かないと予想されるため、いきなり選択圧を
   入れると「効果が測れないものに最適化する」ことになる
2. 測定だけなら既存の択評価の再利用で安く、診断の表示価値はすぐ出る
3. 過去の教訓 (もっともらしい仮説の実測棄却: 選出注入・探索ハイブリッド・
   v2特徴量) に従い、**相関の実測 (Phase B) を選択圧 (Phase C) の前提にする**
