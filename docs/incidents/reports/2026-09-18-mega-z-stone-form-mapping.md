# 2026-09-18 メガ Z 石のフォルム対応の誤り: ガブリアスナイトZ の型が通常のメガガブリアスとして評価されていた

## 1. サマリ

- 発生: 2026-09-11 (レギュレーション M-C の切替でメガ〇〇Z が使用可能になり、使用率データにその石を持つ型が入り始めた日)。
  検知: 2026-09-18 (ユーザー指摘「ガブリアスについてもメガ Z が登場している」を受けた調査で、石 → フォルムの推定が
  末尾 x / y しか見ていないことを確認)。復旧: 2026-09-18 (対応表引きへの修正をコミット 3e84971d)。
- 影響: 構築提案の探索段 (S3 の被覆・S5 の並びの採点・S6 の型の採点と能力ポイントの微調整・規則のエース判定) で、
  Z 石を持つ型は **通常のメガ (末尾なし) の種族値・タイプで評価されていた**。今期の使用率 1 位のガブリアスの代表型が
  ガブリアスナイトZ (石の使用率 35.3%) なので、脅威 30 種のうち重み最大の 1 種が別の姿だった。
  助言 (接続テスト) と学習・測定の対戦 (Showdown) は影響なし (下記 4 章)。
- 失われた生データ: なし。失われたのは探索段の採点の妥当性 (候補の順位) と、その候補を測定した時間の一部。

## 2. 前提

- ポケモンチャンピオンズのメガシンカは持ち物 (メガストーン) で決まり、1 種に複数のフォルム (X / Y、M-C からは Z) がある。
  図鑑 (advisor/data/dex.json、champions_agent/data/champions_dex.json) はフォルムごとの種族値・タイプ・特性と、
  `requiredItem` (そのフォルムに要る石) を持つ。
- 構築提案 (tools/team_build) は「型 (技・持ち物・特性・配分)」から対面の期待値 (Interaction Matrix、
  `tools/team_build/interaction.view_from_set`) を計算し、メガ石を持つ型はメガ後の姿で評価する。
  この「石 → メガ後の姿」の解決は、2026-09-11 に X / Y の取り違え (ライチュウナイトY → megax に倒れる) を直したときから
  「石の id の末尾が x か y ならその接尾辞、無ければ mega → megax → megay の順に図鑑にある id」という推定だった。
- 同じ推定は助言側にもあった: `advisor/team_advice.py` (登録チームの診断でメガ後の性能を使う)、
  `advisor/engine.py` (メガシンカを切るタイミングの比較)、`advisor/infer.py` (メガフォルムの表示名とベース種への丸め)、
  `champions_agent/env/ranked_teams.py` / `team_builder.py` / `search_expert.py` (メガページの参照・種族名の正規化)。
- 石 → フォルムの正しい表は既にあった: `advisor/gimmick.stone_table()` (champions_dex の `isMega` + `requiredItem`)。
  相手のメガシンカ先の推定 (gimmick) はこれを使っていたので正しかった。

## 3. 何が起きたか

1. M-C (9/9 開始) でメガガブリアスZ / メガルカリオZ / メガアブソルZ が追加された。石の id は `garchompitez` / `lucarionitez` /
   `absolitez`、フォルムは `garchompmegaz` / `lucariomegaz` / `absolmegaz`。図鑑と名前表 (メガガブリアスZ 等) は 9/11 に更新済み。
2. `view_from_set` の推定 (修正前):

   ```python
   suffix = item[-1] if item[-1] in ("x", "y") else ""
   cands = [sid + "mega" + suffix] if suffix else [sid + "mega", sid + "megax", sid + "megay"]
   ```

   `garchompitez` の末尾は z なので接尾辞なし → `garchompmega` (通常のメガ: A170 / B115 / C120 / D95 / S92、ドラゴン・じめん) を採用。
   正しくは `garchompmegaz` (A130 / B85 / C141 / D85 / S151、ドラゴン単)。特性もメガ後の表引きで別フォルムのものになる。
3. 9/12 以降の使用率スナップショットで、ガブリアスの代表型 (最多の持ち物) が ガブリアスナイトZ になった
   (9/18 時点の持ち物: ナイトZ 35.3% / スカーフ 19.0% / タスキ 16.6% / オボン 12.2% / ゴツゴツメット 10.3%)。
   脅威リストの先頭 (使用率 59.5%、重み最大) が別の姿で評価されるようになった。
4. 気付けたはずのサイン: free_0917 の候補 L16_C021 の型生成 (gen:mega) が ガブリアスナイトZ に
   りゅうせいぐん / かえんほうしゃ (特殊技) を選んでいた。生成側 (gen_sets) は requiredItem の表でフォルムを引くので Z 形態 (C141) を
   正しく見ていたが、同じ型を採点する側 (view_from_set) は A170 の通常メガで評価していた。同じ型を 2 か所が別の姿で扱う矛盾は
   記録 (s06_sets.json の notes `gen:mega:garchompmegaz` と対面表の `garchompmega`) に残っていた。

## 6. なぜ防げなかったか

- 9/11 の M-C 切替では「図鑑 / 名前表 / mod の解禁フラグ」を確認したが、**石 → フォルムの推定が複数箇所にコピーされていた**
  ことを洗い出していない。表 (gimmick.stone_table) が既にあるのに使われていなかった。
- 回帰テストは X / Y の取り違え (test_mega_stone_xy_maps_to_form) だけで、新しい接尾辞 (Z) を想定していなかった。
- 気付けたサイン (3 章 4): 型生成側と採点側で同じ型のフォルムが食い違う記録。突き合わせる検査が無かった。

## 8. 恒久対策

- `advisor/gimmick.stone_form_of(species_id, item_id, item_ja)`: 石の id は requiredItem の表で引き、無ければ名前の末尾 (X / Y / Z)、
  それも無ければ 無印 → X。これを唯一の解決にし、`tools/team_build/interaction.view_from_set`、`run.mega_capable_ids`、
  `advisor/team_advice`、`advisor/engine` の `_mega_timing_note`、`advisor/infer` (表示名・ベース種の丸め)、
  `champions_agent/env/ranked_teams` / `team_builder` / `search_expert` (末尾処理) を差し替えた (commit 3e84971d)。
- 回帰テスト: `tests/test_gimmick.py::test_stone_form_of`、`tests/test_team_build_interaction.py::test_mega_stone_z_maps_to_form`
  (ガブリアスナイトZ → garchompmegaz、C141 / S151 / ドラゴン単)、`tests/test_ja_names.py` (メガガブリアスZ)。
- 学習への影響なし (training_changes.json への追記は不要。対戦はシミュレータが正しく処理していた)。

## 9. 教訓 / 未対応の課題

- 「id の文字列を切って推定する」処理は、表があるなら表を使う。同じ推定が複数箇所に増えたら一つに寄せる。
- レギュレーション切替のランブック (docs/REGULATION_CHANGE_RUNBOOK.md) に「新しいフォルムの接尾辞 (X/Y/Z…) が増えたら
  石 → フォルムの解決と表示名の全経路を確認する」を足す。
- 未対応: 型生成側 (gen_sets) と採点側 (interaction) で同じ型のフォルムが一致するかの検査 (invariants) は未実装。
  free_0917 / improve_20260916_0406 の探索段の回し直しは判断待ち。
