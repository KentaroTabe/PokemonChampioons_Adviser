## 3. 何が起きたか

### 3-1. 持ち物 (Z 石)

1. 登録名「メガガブリアスZナイト」は名前表の「ガブリアスナイトZ」と接尾辞の位置が違う。`resolve` の文字列類似は
   無印の「ガブリアスナイト」を 0.842、Z 石を 0.80 と採点し、閾値 0.8 の経路では **無印 (garchompite)** に、閾値 0.85 / 0.9 の
   経路では **未解決** になっていた (実測: scratch の照合スクリプト)。
2. 選出画面の持ち物欄の OCR は石名の末尾 X/Y/Z を落とす (対戦ログの持ち物: 選出〜command で `garchompite`、
   もっと見る画面で `garchompitez`)。画面の読みが登録より優先されるため、登録が正しくても無印になる。
3. メガシンカの文言も末尾を落とす (OCR 原文「ガプリアスはメガガプリアスにメガシンカした」、対戦ログ 16:12 の battle)。
   文言から種族 id を引く経路が `garchompmega` を採用し、直後に読めた石 `garchompitez` と矛盾した状態で残った。
4. `vision/abilities.mega_form_id` の末尾判定は `mega[xy]?$` で **z を見ていない**。ガブリアスは無印/Z の 2 候補なので
   石 id `garchompitez` を渡しても判別できず None (メガ後の固定特性も付かない)。
5. `advisor/engine._mega_timing_note` の名前フォールバックは `item_ja.endswith("Z")` で、「…Zナイト」の並びを拾えない。

気付けたはずのサイン: 対戦ログ 16:12 の battle で自分の active が `species=garchompmega, item=garchompitez` (フォルムと石の
矛盾) になっていた。第16回の記録 (docs/CONNECTION_TEST_CHECKLIST.md) では持ち物の欄を見ていなかった。

## 6. なぜ防げなかったか

- 「推定」と「確定」を同じフィールドに入れていた。7 体目が生えない (ロスター上限) 対策はあったが、6 枠内の同種 2 体は
  ルール上あり得ないのに検査がなかった。監査の「6 枠に N>6 種」矛盾は既知 (docs/KNOWN_ISSUES.md A3) だったが観察待ちだった。
- 名前 → id の解決は文字列類似で、接尾辞 1 文字の意味を持たない。9/18 の Z 石修正は「id → フォルム」だけを直し、
  「名前 → id」と vision 側のコピー (`mega_form_id`) を洗い出していない (同じ推定が複数箇所にある、という 9/18 の教訓が
  その時点で適用しきれていなかった)。
- 気付けたサイン: 対戦ログの自分の active に `species=garchompmega` と `item=garchompitez` が同居していた。持ち物と
  フォルムの整合を見る検査がなかった。

## 9. 教訓 / 未対応の課題

- 推定と確定は別のフィールド (または印) で持ち、集計・表示・置換の各所で区別する。ルール上あり得ない状態 (同種 2 体) は
  検査に落とし込む。
- 名前の解決は「意味のある 1 文字」(接尾辞) を類似度に任せない。表があるなら表で引く (9/18 の教訓の適用範囲を広げた)。
