# vision層のライブラリ切り出し計画 (2026-09-01)

外部レビューの提案「ゲーム画面からの日本語UI読み取りを独立ライブラリ化する」
の実行計画。**公開 (新規リポジトリ作成・PyPI・外部OSSへのPR) はユーザーの
明示承認を得てから行う** — 本書はその準備と切り出し境界の確定まで。

## 切り出せる汎用部品 (実装の事実確認済み)

| 部品 | 現在地 | 汎用性 | 備考 |
|---|---|---|---|
| 相対座標ゾーン定義 (`_z`, `crop`) | `vision/zones.py` | ◎ 解像度非依存の矩形定義+クロップ。ゲーム固有はゾーン値のみ | 座標セットを差し替えれば任意タイトルに使える |
| 日本語OCR正規化 (`loose_key`, `similarity`) | `vision/normalize.py` | ◎ 清音化・小書き→通常化・カナ/漢字の混同吸収。OCR誤読に強いキー化 | レビューの記述どおり |
| ファジー名前解決 (`NameResolver`) | `vision/normalize.py` | ◎ 辞書 (`vision/data/jp_names.json` 形式) を差し替えれば任意ドメインで使用可 | 辞書自体はポケモン固有なので同梱しない |
| 縁取り文字マスク (`outlined_text_mask`, `white_text_mask`) | `vision/ocr.py` | ○ ゲームUIの白文字+黒縁の存在検知/前処理。しきい値はUI依存 | |
| OCR二段構え (Apple Vision主体+EasyOCRフォールバック) | `vision/ocr.py` | ○ macOS外はEasyOCR、両方無ければ空文字の劣化動作 (2026-09-01対応済み) | |
| 位置つき行OCRのレイアウト非依存パース | `vision/ocr.py` (`apple_ocr_lines`) + `extractors.parse_team_menu_lines` の帯照合パターン | ○ 「ラベル行と数値行のy帯対応付け」はパターンとして汎用 | パーサ本体はゲーム固有なので設計パターンとして文書化 |
| タイプアイコン分類 | `vision/typeicons.py` | △ **dHash (グリフ形状) 主体+Lab色距離フォールバック**。レビューの「Lab+dHashハイブリッド」はおおむね正確だが主従が逆。テンプレート運用込みで汎用化可能 | |
| スプライト同定 (ヒスト相関0.6+dHash0.4) | `vision/spriteid.py` | △ テンプレート自動収集の仕組み込み | |

## 切り出さないもの (プロジェクト固有)

- ゾーン座標値・シーン分類のしきい値 (チャンピオンズのUI前提)
- イベント辞書・状態機械 (`events.py` / `state.py`)
- 図鑑・使用率DL連携 (`advisor/` 以下)
