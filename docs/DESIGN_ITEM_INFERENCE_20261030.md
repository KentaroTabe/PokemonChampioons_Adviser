# 観測から相手の持ち物を推定する手がかりの追加 (設計、2026-10-30)

背景: [docs/EXTERNAL_BATTLE_AI_SURVEY_20261030.md](EXTERNAL_BATTLE_AI_SURVEY_20261030.md) §6 の 4 (天候・フィールドの継続ターン → 持ち物、行動からのこだわり系の推定)。
レビュー 10/30 の条件: ターン数・効果の再発動・交代・読み取り欠落を区別できる証拠から足す。曖昧な観測で候補を断定的に消さない。
関連: [docs/DESIGN_PRIOR_MIXING_20261023.md](DESIGN_PRIOR_MIXING_20261023.md) (事前分布の混合、持ち物は §2.3・§9)。
この文書は設計と予備集計だけ。コードは変えていない。数値の出典は §8 の集計スクリプト (実戦ログは読み取りだけ)。
2026-10-30 レビュー (2 回目) の反映: 順序 (既存の不具合 3 点の修正を先に)、§3.2 の尤度比は暫定値、観測の識別と帰属 (§3.4)、型推定への接続方法 (§3.5)、
評価の分け方 (§5)、開発者判断の記録 (§6.5)。集計はやり直していない (数値は前の版のまま)。

## 0. 要点

- 今の持ち物の推定は「使用率の第一の持ち物を 1 つ (点推定)」+「表示が読めた持ち物で上書き」+「消費・はたきおとすで持ち物なし」。行動からの手がかりは
  `ev_infer` の**同じ技 3 連続 → こだわり (尤度比 40)** と、素早さ・ダメージの観測だけ。天候・フィールド・壁の継続ターンは使っていない。
- 実戦ログ 268 対戦 (2026-07-19〜10-23) の実数:
  - 表示 (「<名前>の<持ち物>」のポップアップ) で判明した相手の持ち物は 138 個体 / 115 対戦。たべのこし 58・きあいのタスキ 33・オボンのみ 27 で 86%。
    **こだわりスカーフ・しめったいわ・グランドコート・ひかりのねんど は相手でも自分でも一度も表示されていない** (自分の登録で場に出た スカーフ 63・しめったいわ 60・グランドコート 40・ひかりのねんど 18 個体、発火 0)。
  - 使用率 DB (snapshot 75) の Champions の持ち物に こだわりハチマキ・こだわりメガネ・とつげきチョッキ・あつぞこブーツ・しんかのきせき の行は無い。こだわり系は スカーフ だけ。
  - **同じ技 3 連続は弱い手がかり**: 自分側 (登録 = 正解) で、技を 3 回以上使った個体のうち 3 連続が出たのは スカーフ 6/12、それ以外 41/203 (尤度比 約 2.5)。
    相手側では 3 連続の 36 個体のうち 13 個体が後で スカーフ 以外の持ち物を表示した。今の尤度比 40 は強すぎる。
  - **交代なしに違う技 2 つ (こだわりの否定) は有力な手がかり**: 自分の スカーフ 持ちで技を 2 回以上使った 36 個体のうち否定が出たのは 1 (わるあがき)、それ以外は 213/367。
    相手側では 550 個体中 219 個体で出ている (守りの条件を満たすのは 134)。ただし件数は 35 で、同じプレイヤー・チームの繰り返し観測 (§3.2)。
  - 天候の終了の文言はほとんど読めていない: 後の開始で上書きされず、ターンの数え上で必ず終わっているはずの 17 回のうち、終了の文言を読めたのは 5 回。
    ターンの数え方の誤差も大きい (自分の しめったいわ の雨の終了までのターン数が 1〜18、正しくは 8 以下)。**継続ターンを数える手がかりは今のままでは使えない**。
  - 場の状況画面のターン表示 n/m の m は延長を示すと見られる (残り 6 を読んだ 2 例はどちらも自分の しめったいわ / グランドコート)。ただし m の値は記録しておらず、
    m の意味・読み取り精度は未確認 (§7)。
  - 交代の文言の読み落とし: 状態の場の個体が交代の発火なしに変わった回数が相手 151/619 (24%)、自分 193/690 (28%)。
- 規則: 事前分布 (使用率) × 尤度の積で更新する。**候補を消してよいのは表示の文言と消費・喪失の観測だけ**。それ以外は尤度比を [下限, 上限] に収め、0 にしない。
  文言が無いこと (終了の文言・たべのこし の回復が出ない) は証拠に数えない。続けて起きる観測 (2 つの技) は、時刻だけでなく個体・出場区間・技の実行イベント・
  持ち物変更区間を識別して結び付け、識別できなければ更新しない (§3.4)。
- **§3.2 の尤度比は全部暫定値** (2026-10-30 レビュー): 集計は §3.4 の条件を全部当てたものではなく、条件を当てると分母も分子も変わる。
  否定の 0.15 は「弱めに設定した暫定値」(統計的に保証された保守値ではない)。3 連続の 2 は候補で、実装する検出条件で再集計して 事前分布のみ・現行 40・候補 2 を比べてから決める。
  場の状況画面の m は推定に使わず記録だけ (画面の m の意味・読み取り精度・設定者への帰属の確認が先)。
- 型推定への接続 (§3.5): 別の持ち物の分布を持たず、固定した事前分布 (data_pin の版) で作った既存の「配分 × 持ち物」の仮説に、新しい観測の尤度を一度だけ掛ける。
  持ち物の分布はその仮説から集計する。
- 順序 (2026-10-30 レビュー、§6.2): **先に既存の不具合 3 点を直す** — 型推定が data_pin の版の固定を通らない、`observe_item` がサーバーの経路で呼ばれない、
  自分の延長の持ち物の天候・フィールドを vision が 5 ターンで消す (§6.4 の論点 3・4・5。レビュワーがコード上で再現。対応済み (feature/team-build に 2026-10-31 マージ))。
  その後に (1) 守りの条件を実装したこだわりの否定、(2) 同じ技 3 連続の比 40 と候補 2 の比較。場の状況画面の m の記録は較正を待たずに準備してよい。
- 評価 (§5): 相手側 = 後に表示された持ち物に対する改善を測る (表示されない持ち物、特に スカーフ への安全性は結論にしない)。自分側 = 値を決めたデータとは別の時期・セッションで
  スカーフ の誤否定を測る (正解は観測時点の持ち物)。再現テスト = 交代の見落とし・重複文言・持ち物変更で誤更新しないこと。

### 1.1 推定の経路 (コードを読んだ範囲)

> 注記 (2026-10-31): この表は執筆時点 (10/30、fd03b060) の現状。太字の 3 点 (data_pin の版の固定、`observe_item` の未呼出、継続ターンの 5) は §6.4 の論点 3・4・5 で対応済み。

| 段 | 場所 | 何をしているか |
|---|---|---|
| 事前分布 (助言の点推定) | `advisor/sets.py` `SetPredictor.predict(sid)["items"]` | 使用率 DB の上位 4 を合計 100 に正規化。版は `advisor/data_pin` で固定できる |
| 点推定の採用 | `advisor/engine.py` `opponent_move_pool` | 持ち物が観測されておらず `item_removed` でなければ、上の第一の持ち物を `opp_view.item` に入れる |
| 型推定 (性格・努力値・持ち物) | `advisor/ev_infer.py` `SpreadEstimator` | 仮説 = DB の配分 × 持ち物 (上位 4、`_champions_filter` の全 snapshot の合計。**data_pin の版の固定は通らない**。対応済み (feature/team-build に 2026-10-31 マージ)、§6.4 の論点 3)。`best()` の確度が 0.25 以上で観測 1 件以上なら、engine は持ち物もその仮説のものにする (`engine.py` の型推定の差し替え) |
| 　素早さ | `observe_speed` | 同じ優先度の先後で、矛盾する仮説 ×0.2。仮説の持ち物が スカーフ なら実効素早さ ×1.5 で比べるので、**スカーフ の手がかりにもなっている** |
| 　ダメージ | `observe_damage` | 計算の範囲 ±3% の外は正規分布 (幅 6%) で減衰。仮説の持ち物 (いのちのたま 等) がダメージに入る |
| 　こだわりの固定 | `observe_choice_lock` (`SpreadTracker._on_frame`) | 同じ種の同じ技が 3 回続いたら (switch_opponent で全部の連続を切る) こだわり系 ×4、それ以外 ×0.1 (比 40)。1 個体 1 回だけ |
| 　持ち物の判明 | `observe_item` | 判明した持ち物以外 ×1e-6。仮説 (上位 4) に無い持ち物なら何もしない。**サーバーの経路では呼ばれていない** (呼ぶのは `champions_agent/env/search_expert.py` だけ)。サーバーでは判明した持ち物が `opp_view.item` を上書きするので助言の持ち物は正しいが、努力値の仮説は判明前の持ち物の仮説のまま (対応済み (feature/team-build に 2026-10-31 マージ)、§6.4 の論点 4) |
| 表示の読み取り | `vision/events.py` `_parse_popup` | 「<名前>の<特性 or 持ち物>」を全分割で照合 (特性が優先)。持ち物なら `item_id` を入れ、`_apply_item_activation` (`advisor/data/item_effects.json`) で回復・ランク・消費を反映 |
| 文言の辞書 | `vision/events.py` `SIMPLE_EVENTS` | 持ち物は たべのこし の回復・タスキ の「こらえた」・いのちのたま の反動・ふうせん。天候の開始と終了 (開始で `weather_turns = 5`)、フィールド、壁の終了 |
| 喪失 | `_parse_knockoff` | はたきおとす で `item_removed`。以後、登録・使用率で持ち物を戻さない |
| 継続ターン | `vision/pipeline.py` `_tick_field_effects` | 新しいターンごとに残りを 1 減らし 0 で消す (壁も陣営ごとに同じ、2026-10-31)。開始は文言・特性で 5、場の状況画面 (`extract_field_check`) の n/m を読めたら m − n。自分の延長の持ち物でも 5 で消す (対応済み (feature/team-build に 2026-10-31 マージ)、§6.4 の論点 5) |
| 矛盾の除去 | `advisor/scoring_transition.py` `_drop_contradicted_item` | 消費・喪失なら持ち物なし。とつげきチョッキ の仮定は変化技を見たら外す |
| こだわりの技の固定 (相手) | `scoring_transition.restrict_opp_pool` | **観測で確定した** こだわり系 (`item_id`) のときだけ直前の技に固定。相手の スカーフ が判明したことが無いので、実戦では一度も条件を満たしていない (§1.2) |
| 持ち物の感度 | `scoring_transition` (`TRANSITION_SENSITIVITY_ITEMS` = スカーフ / タスキ) | 観測が無ければ有無を入れ替えた仮説で第一候補が変わるかを見る。実機の既定は off |

- `item_id` / `item_consumed` / `item_removed` は `vision/state.PokemonState` の欄で、advice 行の state (版 2) に `item` / `item_consumed` / `item_removed` / `item_ja` として残る。
  使用率からの推定は state に入らない (`battle_logger.py` の注記)。`ev_infer` の推定は advice 行の `ev_infer` (10/20〜) に残る。

## 3. 推定の規則

### 3.1 形

- 個体 (対戦 × 相手の枠) ごとに、既存の型推定 (`ev_infer`) の仮説 = 「配分 × 持ち物」を使う。事前の重みは data_pin で版を固定した使用率から作る
  (今は版の固定を通らない。§6.4 の論点 3 の修正が前提)。持ち物の分布 q(item) は別に持たず、仮説の重みを持ち物ごとに合計して集計する (§3.5、2026-10-30 レビュー)。
  一覧に無い持ち物は、表示で判明したら候補に追加する (`observe_item` の修正、§3.5)。
- 観測 e ごとに、その個体の各仮説の重みに log L(e | 仮説の持ち物) を一度だけ足し、集計のときに正規化する。L は §3.2 の表 (版を付けて config に置く)。
- 観測は「その時点までに読めたもの」だけ。後の観測で前の観測を取り消すときは、記録 (§4) から計算し直す (足し引きで戻さない)。
- 計算は純粋関数 (例 `apply_item_cues(hyps, cues, table) -> hyps` と、仮説から持ち物の周辺分布を出す集計) に分け、トラッカー (副作用側) は観測を集めるだけにする。

### 3.2 尤度の表 (暫定値。§5.1 の較正で決め直す)

尤度比は「その観測が出る確率の、持ち物ごとの比」。スカーフ 以外の持ち物を 1 として書く。

**表の値は全部暫定値** (2026-10-30 レビュー): 元の集計 (§1.2) は §3.4 の条件 (処理の空白・観測間隔・アンコール・へんしん・持ち物変更、個体と出場区間の識別) を
全部当てたものではない。条件を当てると、否定・3 連続の分母 (技を 2 回 / 3 回以上使った個体) も分子も変わる。値は実装する検出条件で再集計してから決める。

| 観測 e | L(e \| スカーフ) | L(e \| 延長の持ち物) | L(e \| ほか) | 値の位置づけ |
|---|---|---|---|---|
| 表示の文言で持ち物 X | X なら 1、ほか 0 | 同左 | 同左 | 断定 (既存) |
| 消費・喪失 | 持ち物なし (既存) | | | 断定 (既存) |
| 交代・ひんしなしに違う技 2 つ (§3.4 の条件つき) | 0.15 | 1 | 1 | **弱めに設定した暫定値**。下記 |
| 同じ技 3 連続 (3 回とも別の実行イベント・間隔つき) | 2 (候補) | 1 | 1 | **候補**。現行は 40。下記 |
| 場の状況画面 m = 8 (その効果を設定した個体) | — | — | — | **推定に使わず記録だけ** (候補は 延長の持ち物 20)。下記 |
| 場の状況画面 m = 5 (同上) | — | — | — | **推定に使わず記録だけ** (候補は 延長の持ち物 0.1)。下記 |
| 先後・ダメージ | 既存の `observe_speed` / `observe_damage` | | | 既存 |

- **否定の 0.15**: 自分側 0/35 の 3/35 ≒ 0.086 を、スカーフ 以外で否定が出た割合 0.58 で割った値。3/35 は一定の仮定 (個体が独立・同じ確率) の下での誤り率の上限の近似で、
  非スカーフ側の点推定 0.58 で割っても尤度比全体の 95% 上限にはならない。35 個体は同じプレイヤー・チームの繰り返し観測でもある。
  だから「統計的に保証された保守値」ではなく「弱めに設定した暫定値」として扱う (2026-10-30 レビュー)。
- **3 連続の 40 → 2**: 弱める方向はレビューで賛成。ただし 2 が最適・較正済みという根拠は無い (自分側 0.25 / 0.10 = 2.4、3 連続だけなら 0.50 / 0.20 = 2.5 は、§3.4 の条件を当てる前の値)。
  実装する検出条件で再集計し、事前分布のみ・現行 40・候補 2 を同じ観測条件で比べてから決める (§5.2、§6.5 の 2)。
- **m = 8 の 20 / m = 5 の 0.1**: 推定には使わず、記録 (§4) だけを先に入れる。画面の m の意味 (延長を含む合計か)・読み取り精度・設定者への帰属を確かめてから値を決める。

- 尤度比は [ITEM_CUE_LR_MIN, ITEM_CUE_LR_MAX] (例 0.05〜20) に切る。同じ種類の観測は 1 個体 1 回だけ数える (今の `observe_choice_lock` と同じ)。
- 延長の持ち物は効果ごとに 1 つ (雨 = しめったいわ、晴れ = あついいわ、砂 = さらさらいわ、雪 = つめたいいわ、フィールド = グランドコート、壁 = ひかりのねんど)。
  この対応と基本の継続ターン (5 / 8) はゲームの数値なので `advisor/data/field_effects.json` に置く (実装規則 1。今は `vision/events.py` と `vision/pipeline.py` に 5 が直書き)。

### 3.3 候補を消してよい観測

- 消す (尤度 0) のは **表示の文言で持ち物が読めた** ときと **消費・喪失を読めた** ときだけ。今の `item_id` / `item_consumed` / `item_removed` の扱いのまま。
- それ以外の観測は、どれだけ強くても尤度比を下限で止める。複数の観測が重なれば結果として小さくなるが、0 にはならない。
- 表示の文言も帰属の誤り (別の個体の名前に解決) はありうるので、帰属が確かでない表示 (`_parse_popup` が名前で個体を決められない) は今どおり捨てる。

### 3.4 読み取り欠落・効果の再発動・交代の扱い、観測の識別と帰属

- **文言が無いことは証拠にしない**: 終了の文言・たべのこし の回復・タスキ の発動が出ないことからは何も更新しない。
- **不確かな続けて起きる観測は使わない** (下記の条件と識別を満たさない組は、否定にも肯定にも数えない)。
- **観測の識別と帰属** (2026-10-30 レビューで追加): 時刻の条件だけでは足りない。
  (a) フレームを処理し続けていても、交代や持ち物変更を認識できたとは限らない (処理の空白が無いことは、交代の文言を読めたことを意味しない)。
  (b) 時刻が離れていても、同じ技の文言の再読み (同じ 1 回の実行を 2 回数える) の可能性がある。
  (c) 同じ基本種が場にいても、一度交代して戻った (別の出場区間) 可能性がある。
  だから観測は、**個体** (対戦 × 相手の枠)・**出場区間** (場に出てから下がるまで)・**技の実行イベント** (1 回の技の実行)・**持ち物変更区間** (はたきおとす・トリック・消費の前後) を
  識別して結び付ける。2 つの技が同じ個体の同じ出場区間・同じ持ち物変更区間の、別々の実行イベントだと識別できないときは更新しない。
  識別の具体的な方法 (どの発火・状態の欄で区間を切るか) は実装の段階で決め、§5.3 の再現テストで確かめる。
- **続けて起きる観測** (違う技 2 つ、同じ技 3 連続) は、上の識別に加えて次の全部を満たすときだけ使う:
  1. 間に、その側の交代・ひんしの発火が無い。
  2. 間の状態で、場の個体 (基本種) がずっと同じ (交代の文言を読み落とした疑いを除く。§1.2 の 24%)。
  3. 間に処理の空白 (処理したフレームの間隔 > `ITEM_CUE_MAX_GAP_SEC`) が無い。トラッカーは毎フレーム呼ばれるので vision を変えずに測れる。
  4. 2 つの技の時刻の差が `ITEM_CUE_MIN_SEP_SEC` 以上 (同じ文言の再読みの重複を数えない。`EVENT_DEDUP_SEC` の注記の「正当な連続は 1 ターン = 30 秒以上」)。
     turn の値は数え漏れがあるので、時刻で判定する (turn が同じ組 77/216 を全部捨てると正しい否定も捨てる)。
     ただし時刻の差だけでは再読みを除けない (上の (b))。技の実行イベントの識別と併せて使う (2026-10-30 レビュー)。
  5. どちらの技も わるあがき・アンコール中の技・へんしん の写しでない (`transform_masked` と同じ考え)。
  満たさない組は「使わない」(否定にも肯定にも数えない)。
- **こだわりが外れる事象**: はたきおとす (`item_removed`)・トリック 等で持ち物が変わったら、それ以前のこだわりの観測はその個体の新しい持ち物に使わない。
- **効果の再発動・上書き**: 天候は出るたびに設定し直される (再発動 20、上書き 51 / 93 対戦)。継続ターンの観測は「最後の設定から」だけを見る。
  上書き・再発動を読み落とした可能性 (間に処理の空白、または場に出た個体が設定の特性を持つのに特性の表示が無い) があれば、ターン数の観測は使わない。
  場の状況画面の n/m は設定からの経過と合計を画面が直接出す (と見られる、§7) のでターンの数え上げの誤差は受けないが、**再発動・上書きの問題を受けないわけではない**
  (2026-10-30 レビューで訂正。前の版は「この問題を受けない」と書いていた)。m が正しく読めても、その m を設定した個体を取り違えれば別の個体の持ち物を推定する。
  m を持ち物の観測にするには、画面を開いた時点で有効な効果の**最後の発動**と、その**設定者**への対応が要る。対応が付かない m は記録だけにする。
- **設定した個体の帰属**: 特性の表示 (側と名前つき) または技の使用 (側つき) で決まった開始だけを使う。文言だけの開始 (17 回) は設定した個体が分からないので使わない。
  壁は自分と相手の両方が張るので、終了の文言の「相手の / 味方の」で側を合わせる。

### 3.5 既存の更新との関係 (接続方法、2026-10-30 レビューで確定)

- **接続方法 (最初の形)**: 現行の型仮説 (`ev_infer` の「配分 × 持ち物」) には持ち物の事前確率が既に入っている。別に持った持ち物の事後分布をその仮説にそのまま掛けると、
  事前分布と観測を二重に数える。だから最初は次の形にする:
  1. 固定した共通の事前分布 (data_pin の版) から仮説を作る (§6.4 の論点 3 の修正が前提)。
  2. 新しい観測 (否定・3 連続) の尤度を、既存の仮説に**一度だけ**掛ける (同じ観測を別の経路でもう一度掛けない)。
  3. 持ち物の分布は、その仮説の重みを持ち物ごとに合計して集計する。持ち物だけの分布を別に維持しない。
- **代案 (最初の形では採らない。代案として残す)**: 持ち物の分布を別に維持し、`ev_infer` には「持ち物の分布で重みを付け直した仮説」を渡す。採るなら、事前分布をどちらが持つか、
  観測をどちらが掛けるか (両方で掛けない)、どちらが記録・再生の正とするかの更新責任を明記する。前の版の §3.5 の案 (`sets` 側で分布を持ち `ev_infer` に重みを渡す) はこちら。
- `observe_item` (§6.4 の論点 4、対応済み (feature/team-build に 2026-10-31 マージ)) に求めること: (1) 上位候補に無い持ち物が表示で判明したら、その持ち物の仮説を候補に追加できる (今は何もしない)。
  (2) 消費・喪失は「以前持っていた物」(消費したきのみ・はたきおとされた物) と「現在の持ち物なし」を分けて扱う。
- `observe_choice_lock` の比 40 は §3.2 の候補 2 と比べてから置き換える (既存の挙動の変更。§6.5 の 2)。
- 否定は `SpreadTracker._on_frame` の連続の追跡に足す (今は同じ技の連続だけを見ていて、違う技が来ても何もしない)。§3.4 の識別を満たす組だけ。

## 4. 記録と再生

- **観測を残す** (advice 行の state、版 2 の欄を足す): 相手の個体に `item_cues` を足す。各要素は
  `{"kind": "choice_negated" | "choice_repeat3" | "field_total", "t": 秒, "turn": n, "detail": {...}}`
  (detail は 2 つの技 id と時刻、または効果と m)。観測だけで、計算した尤度は入れない。
  `MON_STATE_ADDED_FIELDS` と同じ扱い (必ず書く・無ければ null、`MON_V2_FIELDS` には入れない = 前の版 2 の行を欄の欠けに数えない)。
- **場の状況画面の m を残す**: `FieldState` に `weather_total` / `terrain_total` と、壁の合計 (側ごと) を足す。設定した個体 `weather_setter` / `terrain_setter`
  (`{"side", "species", "t", "src"}`) も足す。field は scene 行・advice 行の state にそのまま入るので、両方に出る (欄を足すだけ。旧版の行は欄が無い = 不明として読む)。
- **推定の結果を残す**: advice 行 (kind = battle) に `item_post` を足す (`ev_infer` と同じ置き方): `{種族 id: {"dist": [[item, p], ...], "prior_snapshot": id,
  "table_version": n, "n_cues": k}}`。`dist` は型仮説の重みを持ち物ごとに合計した集計 (§3.5。別に維持した分布ではない)。
  表の版は config (`ITEM_CUE_TABLE_VERSION`) に置き、version 行の rules の digest に入れる。
- m の記録 (上) には、画面を開いた時点の効果の最後の発動 (時刻・信号) と設定者の帰属が付いているかも残す (§3.4。付かない m は推定に使えない)。
- **再生で同じ推定になること**:
  1. 復元 (`tools.advice_replay`) は `item_cues` と field の欄を state に戻す。
  2. 版を固定した事前分布から仮説を作り、`item_cues` と表の版で尤度を掛け直して集計し、記録の `item_post` と一致することをテストで確かめる (純粋関数なので外部環境なしで書ける)。
     ただし型仮説には先後・ダメージの観測 (`observe_speed` / `observe_damage`) も掛かるので、`item_post` を計算し直すにはそれらの観測の記録も要る。
     今の advice 行の `ev_infer` の記録で足りるかは未確認 (§6.4 の論点 9)。
  3. 助言の再生は、今の `ev_infer_override` と同じく、記録の `item_post` を state に入れて engine がトラッカーより優先して読む経路を用意する。

## 5. 評価の設計

### 5.1 自分側で手がかりを較正する (正解 = 登録)

- 自分の個体は登録で持ち物が分かる (表示の出ない スカーフ・しめったいわ・グランドコート・ひかりのねんど も含む)。手がかりの検出 (§3.4 の条件つき) を自分側の発火に同じ規則で当て、
  P(観測 | 持ち物の種類) を数える。尤度比の初期値 (§3.2) はここから決め、相手側の評価には使わない (同じデータで決めて測らない)。
- 前提: 自分のプレイ (同じ技を続けるか) と相手のプレイは違いうる。否定 (違う技を使ったら スカーフ でない) はルールで決まる現象なのでプレイの差の影響が小さいが、
  3 連続の割合はプレイに強く依存する。3 連続の尤度比は上限を低く置く (§3.2 の 2)。
- 今の件数: スカーフ で技 2 回以上 36 (否定 0、わるあがき除く)、技 3 回以上 12。延長の持ち物で場の状況画面の m を読んだ例 2 (m の記録が無いので下限)。
- **誤否定の測定は別のデータで** (2026-10-30 レビュー): 値を決めたデータ (今の 268 対戦) とは別の時期・セッションの自分側の対戦で、スカーフ の誤否定 (スカーフ 持ちに否定が出た割合) を測る。
  正解は登録時の持ち物ではなく**観測時点の持ち物**に合わせる (消費・はたきおとす・トリック の後は変わる)。

### 5.2 相手側で予測を比べる (正解 = 後に判明した持ち物)

- 標本: 相手の個体ごとに、初めて表示で判明した持ち物 (状態行の `item` の最初の値。marble・メガストーンは除く) を 1 標本にする (DESIGN_PRIOR_MIXING §9.3 と同じ数え方)。
- 予測の時点: 判明より前の最後の advice 行。入力はその時刻より前に読めた観測だけ (判明した表示そのもの、判明の後の観測は入れない)。
- 除外: 予測時点で種が推定 (未確定) の標本は主評価で除外する (DESIGN_PRIOR_MIXING §9.3 と同じ)。使うなら別の探索的集計にし、後で確定した種に置き換えない (§6.5 の 1)。
- 比べる予測: (a) 事前分布だけ、(b) 今の規則 (3 連続の比 40)、(c) §3.2 の表 (3 連続は候補 2)。(b) と (c) の 3 連続は同じ検出条件 (§3.4) で数える。
  指標は正解の対数尤度の平均と top-1 の正解率。
  対戦単位のブートストラップで差の区間 (DESIGN_PRIOR_MIXING §9.3 と同じ)。事前分布の snapshot は対戦の前のものを選ぶか、固定 (75) にして漏れの件数を出す。
- **この評価で言えること** (2026-10-30 レビュー): 後に表示された持ち物に対する改善だけ。正解は表示の出る持ち物だけで、スカーフ・延長の持ち物は正解に現れない。
  だから (c) が スカーフ の重みを下げる方向の誤り (本当は スカーフ なのに否定した) はここでは測れず、**表示されない持ち物への安全性はこの評価から結論にしない**
  (スカーフ を下げる規則が高得点でも、本物の スカーフ を誤って下げる害が無いことにはならない)。その害は §5.1 の別データの誤否定と §5.3 の再現テストで見る。
  逆向き (3 連続で スカーフ を上げすぎた) は測れる (相手の 3 連続 36 個体のうち 13 個体が後に別の持ち物)。
- 層: 手がかりが判明の前にあった標本 (否定 34、3 連続 4) と無かった標本 (104) を分けて出す。無かった標本では (a)〜(c) が同じになるはずなので、その一致を確かめる。

### 5.3 再現テストと決定再生

- **再現テスト** (2026-10-30 レビューで追加): 次の場面で誤って更新しないことを、組み立てた発火・状態の列で確かめる (外部環境なし)。
  1. 交代の見落とし: 交代の文言が無いまま、同じ基本種が一度下がって戻った / 別の個体に変わった列で、否定・3 連続を数えない。
  2. 重複文言: 同じ 1 回の技の実行の文言が、時刻を離れて 2 回読まれた列で、3 連続に数えない。
  3. 持ち物変更: はたきおとす・トリック・消費をまたぐ観測を、変更後の持ち物に使わない。
- 決定再生: 推定が変わった局面で第一候補が変わるかを、`tools.advice_replay` の再生で数える (`item_post` を入れ替えて比べる)。版 2 の対戦が要るので、新しい対戦が溜まってから。

### 5.4 必要な件数の見積もり

- 相手側 (5.2): 判明した持ち物の標本 138 (115 対戦。7 月 45 / 8 月 36 / 9 月 36 / 10 月 21)、うち手がかりが判明より前にあるのは 34 + 4。
  否定が効く標本では正解は スカーフ でないので、(c) は必ず対数尤度を上げる (差の大きさは事前分布の スカーフ の割合で決まる)。
  だから相手側の差は「表示された持ち物に対する改善」の大きさを示すだけで、スカーフ を誤って下げる害の有無はここでは測れない (§5.2。前の版の「害が無いかを見る用途なので
  件数は今のままで足りる」は誤りなので削除した、2026-10-30 レビュー)。
- 自分側 (5.1) が決め手: 否定の誤り率を 95% で 5% 以下と言うには (3 の法則) スカーフ で技 2 回以上の個体が 60 以上要る。今 36 (35)。
  この件数は値を決めたデータとは別の時期・セッションで数える (§5.1)。
  3 連続の割合 6/12 の 95% 区間 (Clopper–Pearson) は約 0.21〜0.79 で、±0.1 に絞るには技 3 回以上の スカーフ 持ちが約 100 要る (今の構築の頻度では当分届かない) — だから比を低く固定する。
- 場の状況画面の m: m を記録し始めてからの件数で決める。今は 2 例 (64 対戦で画面を開いたのは 92 回、効果が出ていたときに開いたかは未集計)。
