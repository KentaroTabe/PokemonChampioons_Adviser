# RL構造変更の設計: 観測v7 + Set Encoder

作成: 2026-08-09。プラトー (current 0.56〜0.59 が6日横ばい) と
構造化レバーの枯渇 (報酬・選出・カリキュラム・探索複合はすべて決着) を受けた
最後の大レバー。弱点分析の知見「負けの49%は相手残り1体の取り逃しだが、
原因は中盤の交換効率」を設計の起点にする。

## 1. 観測v7 (+32次元, 388→420)

従来どおり**末尾追記でv1〜v6のプレフィックスを不変に保つ**。
`policy_battle._adapt_obs` のスライス機構により、旧388チェックポイント
(本番の`_best`含む) は新エンコーダの下でもそのまま動く。

| ブロック | 次元 | 中身 | 狙い |
|---|---|---|---|
| ダメージレース | 6 | 自HP計/3, 相手HP計/3 (未視認=満タン扱い), HP差, 自残数/3, 相残数/3, 残数差 | 「この交換は得か損か」の直接観測。中盤の交換効率に対応 |
| 自控え詳細 ×2 | 14 | 種族値6/255 + 対面の素早さ比較1 (×2体) | 交代判断の材料。従来の控えはタイプ+HPのみで種族値が見えなかった |
| 相手控え種族値 ×2 | 12 | 種族値6/255 (視認済みのみ、×2体) | 同上 (相手側) |

見送った候補: 択gap値 (学習時に探索が要り fps -30%以上) /
こだわりロック推定 (訓練側に情報源がなくパリティが崩れる) /
履歴特徴 (リカレント化が必要。set encoderの次の段)。

## 2. Set Encoder (アーキテクチャ変更)

現在: 420次元を平坦なまま MLP 512×512 へ。
変更: パーティを**エンティティ (ポケモン) 単位の集合**として扱う。

```
obs(420) ─ 名前付きブロックのオフセット表 (spaces.OBS_PARTS) で分解
  ├─ エンティティ6体 (自アクティブ/自控え×2/相アクティブ/相控え×2)
  │    各: 固有ブロックを連結 + エンティティ種別one-hot(6) → 共通MLP(→96)
  │    → Multi-head self-attention (1層, 4head) → mean-pool
  ├─ グローバル (場/天候/レース等の残り全ブロック) → MLP(→128)
  └─ concat [自アクティブ埋め込み, pooled, グローバル] → 512 → PPOトランク
```

- 共通MLPの重み共有により「ポケモンの評価方法」を6体で共有し、
  サンプル効率を上げる (平坦MLPは6体分を別々の重みで学び直している)
- 実装は SB3 の `features_extractor_class`。`TRAIN_ARCH=set` 環境変数で
  切替、既定は従来MLP (本番は移行判定まで不変)
- ブロック→エンティティ対応は encoders.py が生成する **OBS_PARTS
  (名前→オフセット表)** から機械的に構築する。手書きのインデックスは
  使わない (388次元の平坦レイアウトに手でスライスを書くとv8で必ず壊れる)

## 3. 移行計画 (BC蒸留)

512化 (2026-07-27) と同じ手順の応用:
1. 現行の本番方策 (388入力) を**教師**、新アーキ (420入力) を**生徒**に、
   自己対戦の局面で蒸留する。v7はプレフィックス不変なので、
   教師には `obs[:388]` を与えるだけでよい (bc_pretrain に教師=方策
   モードを追加)
2. 蒸留後、隔離ディレクトリ (sweep方式) で自己対戦を継続
3. **本番は移行判定まで一切変更しない** (touch しないのは checkpoints/
   配下すべて)

## 4. 効果判定 (事前登録)

- **日程: 開始から7日後に判定** (実装2日 + 蒸留・立ち上げ1日 + 学習4日)
- 中間観測: 日次トラッキングに新アーキの定点 (同一シード3,000戦) を追加。
  途中で判定を前倒ししない (勝者の呪い対策)
- **判定基準 (測定前に固定)**:
  - 条件: 新アーキ (隔離学習7日時点) vs 本番current、各10,000戦・
    同一相手列・同時実行
  - 採用: 差 ≥ +0.02 かつ 95%CI下限 > 0 (two_prop_verdict δ=0.02)
  - 棄却: CI上限 < +0.02
  - 判定不能: 学習をさらに7日延長して1回だけ再判定。なお不能なら棄却

### 追記 (2026-08-12, 停止インシデントを受けた事前登録の更新)

8/11 00:44〜8/12 22:04 の約46時間、Showdownチーム拒否を契機とした
デッドロックで学習が停止した (watchdog導入済み)。継続走行のラウンド数に
余裕があったため、8/16時点でも計画学習量の約95% (約6,300万/6,600万
ステップ) に達する。よってユーザー合意のもと以下とする:

- **判定日は 8/16 のまま変更しない** (学習量ベースで補償されるため)
- **無益性打ち切りを追加**: 8/14 の日次定点で arch_v7 の参考値が
  **0.45 未満**なら、8/16 を待たず棄却して次の分解実験へ進む。
  0.45 = 「残り2日で本番水準 (≈0.58) に届き得る最低ペース」として
  観測前に固定した値であり、結果を見てからは動かさない
- 棄却時の次実験 (事前登録): **v7観測 + 従来MLP** — 観測の寄与と
  アーキテクチャの寄与を分離する (BC込み2日で判定可能)

### 結果 (2026-08-14): Set Encoder は無益性棄却

8/14定点で参考値 **0.226 < 0.45** となり足切り発動。BC初期値 (0.32) から
累計約2,600万ステップで上昇せず、むしろ低下 (0.32→0.27→0.29→0.23)。
「文献的裏付けが強い仮説も実測では落ちる」の6例目。

**分解実験 (v7観測+従来MLP) を同日開始** (logs/arch_v7mlp、
TRAIN_ARCH=mlp 以外は同一条件)。事前登録:
- 無益性足切り: 8/16 の日次定点で参考値 0.45 未満なら棄却
- 判定: 8/17 に vs 本番current 各10,000戦・δ=0.02 (基準は§4と同一)
- これも棄却なら観測v7自体を棚上げし、構造レバーは「測定軸の見直し
  (vs_agents の乖離解析)」へ移る

### 結果 (2026-08-17): v7観測+MLP も棄却 → 観測v7を棚上げ

事前登録どおり 8/17 に本判定を実施 (各10,000戦・同一相手列 opp_seed=20260730・
同時実行・benchmark相手・相性選出、`scripts/run_arch_verdict.sh`)。

| 条件 | 勝率 | 内訳 |
|---|---|---|
| 新条件 arch_v7mlp (current) | **0.475** | 4,750 / 10,000 |
| 基準 本番current | **0.605** | 6,049 / 10,000 |

差 **-0.130** (95%CI -0.144〜-0.116)。棄却条件「CI上限 < +0.02」に対し
上限 -0.116 で **棄却** (判定不能ではない)。結果一式: `logs/verdict/20260817_223917/`

- Set Encoder (8/14 無益性棄却) と合わせ、**観測v7の変更もアーキ変更も
  効果なし**と確定。事前登録どおり観測v7は棚上げし、構造レバーは
  「測定軸の見直し (vs_agents の乖離解析)」へ移る
- ⚠ 判定の前提の欠け: 隔離学習は 8/16 19:41 から判定時点まで**27時間ハング**
  しており、学習量は 18.5M ステップ (計画30M の約62%) で止まっていた。
  8/16 の無益性足切り (日次定点) も未実施。差 -0.130・CI幅±0.014 と
  8/15定点 0.4947 からの横ばいを踏まえると結論が覆る余地は小さいが、
  「学習を続けていれば届いた」の反証にはならない (未確認)。
  ハングの詳細と再発防止は
  [incidents/reports/2026-08-16-isolated-training-hang.md](incidents/reports/2026-08-16-isolated-training-hang.md)
- 8/16 の足切りを実施しないまま本判定へ進んだのは、10,000戦の本判定が
  1,500戦の参考値より厳密であり、かつ判定日を動かさない事前登録に
  従ったため。結果を見てからの選択ではない

Set Encoder 側の検死 (アテンションの学習率感度、エンティティ分解の検証)
は分解実験の判定後に必要なら行う。
- 採用時: 本番チェックポイントを新アーキへ切替 (world switch を
  training_changes.json に記録、ベンチ履歴は同一基準なので比較可能)
- 学習リソース: 新アーキは n_envs=2 で本番 (n_envs=4) と並走。
  本番はプラトー中のため機会損失は小さい

## 5. リスクと既知の罠 (過去の再発防止)

- 観測次元変更 → resume非互換: `_adapt_obs` スライスで旧モデル互換 ✓、
  net_arch不一致検知は既存 (incidents 4-1)
- advisor側パリティ: rl_bridge に v7 を同順で鏡像実装し、
  test_dim_parity を420へ更新 (パリティ喪失は静かな精度低下になる)
- 「もっともらしい仮説」の前例: 直近5仮説が実測棄却。本件も判定日まで
  結論を出さない。set encoder は文献的裏付けが強いが、それは
  探索ハイブリッドも同じだった
