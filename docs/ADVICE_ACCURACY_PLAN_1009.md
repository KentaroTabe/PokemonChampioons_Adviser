# 操縦提案の精度改善の計画 (2026-10-09)

ユーザーの方針は「注釈や説明を足すのではなく、提案そのものをより正確にする」。プレイヤーとの一致率を最適化せず、
入力事実・対戦の仕組みと矛盾する推奨を減らし、その先で対戦成績の改善を検証する。

初版 a6439a7c の調査結果と、コード・実戦ログの再確認を踏まえた改訂。これは実装計画であり、下記の修正や測定は未実施。

## 0. 改訂の結論

1. **入力・形態・合法手 → 行動の結果と相手応手の最小モデル → 変化技の価値 → 応手モデルと対応範囲の拡張**の順にする。
   変化技の価値は相手の応手に依存するため、応手の扱いをすべて後回しにはしない。
2. **技種別の専用処理は使うが、専用の点数式だけで最善手が決まるとは扱わない。** 各技の効果を状態変化として計算し、
   攻撃・交代・変化技を同じ局面評価で比較する。必要な部分だけ次の2〜3ターンまで延ばす。
3. **Showdownロールアウトは条件つきの参照評価であり、「正解手」の生成器にはしない。** 数十回の試行の1位を教師ラベルに固定しない。
   仕様の受入は状態遷移の照合、戦略の正式な採否は既定の対応比較、局面別ロールアウトは原因診断と改善量の見積もりに使う。
4. 上位3型は計算量の上限案として採用する。ただし共同仮説の被覆率・残余確率を記録する。未評価の合法手は低価値と区別し、
   一律に末尾へ落とさない。重い測定は接続テスト・構築run・学習と重ねない。

## 2. 計算の共通契約

### 2.1 入力と行動

- 基本種・現在形態・一時的なタイプ変化を分け、同じ解決結果をダメージ・行動順・RL入力で使う。曖昧な形態を欄0などで強制確定しない。
- 合法性、効果を計算できるか、価値の大小は別の属性にする。選べない行動を負点として順位に残す方式から、候補生成時の制限へ整理する。
  「選べるが条件次第で不発」と「選択自体が不可」も区別する。合法性が未確認の場合の推奨数を別に記録する。
- 行動は技、通常交代、ひんし後の繰り出し、交代技後の繰り出しを区別し、技にはメガあり／なしを持たせる。
- 相手の控えは登録6体すべてを残存戦力としない。判明した選出・ひんし・残数と矛盾しない3体の候補を使う。
- HPの出所・時刻・不確かさを持ち越す。最大HPが既知でも現在HPが満タンとは限らない。直近値も古ければ確定値に戻さない。

### 2.2 共通の状態遷移と局面評価

評価する量は、概念上 `Q(a) = E[V(T(state, a, 相手の応手, 型仮説, 乱数))]` とする。
技種別の処理は `T` (状態変化) と必要な評価期間を担当し、攻撃・変化技・交代で共通の `V` を用いる。

`V` は残存する選出個体、HP、生存、行動順、後続の対面、場の効果などの近似評価であり、較正前に「勝率」と呼ばない。
特徴量・重み・打ち切り評価・スコアの単位を一箇所に定義する。HP損失、ひんし、KOボーナス等の同じ利益・損失を二重に足さない。
最悪応手の評価は期待値と別に保持する。混合する場合も同じ尺度に揃え、既存探索のw=0.15〜0.6を根拠なく流用しない。

各仮説で最適行動を選んでから平均すると、未知の型を知っている操縦になる。**同じ観測情報に対する一つの行動を選ぶ**ため、
各行動について仮説を平均してから順位を決める。後続の行動も、その時点で観測できる情報だけを使う。

### 2.3 遷移処理は一つにする

`search.simulate_turn` を拡張・整理して共通の遷移 `T` に移行する。直接採点用の別エンジンを作って段Dまで並走させる方針は採らない。
依存の循環を避けるため、純粋な状態・行動の型と効果解決は `advisor/transition.py` (新設予定) に抽出し、
`engine.py` と `search.py` の双方から呼ぶ。`damage.py` はダメージ計算、共通遷移は行動順・HP変化・消費・ひんし等の結果を担当する。

- 既存の `search.simulate_turn` は必要なら互換入口として残すが、効果解決の実装は共通遷移へ委譲する。
  確率分岐等で戻り値を変える必要がある場合は呼出し側も同じ変更で更新し、異なる分岐を平均HPに潰して無理に互換性を作らない。
- 最初から全効果を実装せず、登録チームの対象技から移す。未対応は明示し、直接採点と探索で別の効果を捏造しない。
  入力スナップショットは書き換えず、乱数・分岐を引数で再現できる形にする。
- **期待値の変更は仕様修正として認める。** ただし旧挙動の再現、正しい結果の独立した根拠、変更後の状態遷移をテストに残す。
  現行実装が返した値へ合わせるだけの書き換えはしない。API整理と仕様変更は差分・テストで区別できる単位にする。
- `tests/test_search.py`、探索を経由する関連テスト、engineの再現・回帰を同じ統合版で確認する。
  SEARCH_BLEND=0でも探索は実行されるため、結果の形式・例外・所要時間も確認する。共通化は探索の順位統合をONにする変更ではない。

## 3. 段階別の実装と受入

### 3.0 最初の実装単位 (M1)

**段Aの4項目と、段B-2の自滅・HPコストを最初の開発単位とする。** 受入は実ログの再現、状態遷移の一致、
状態→engine→serviceの関連回帰。600戦や実戦局面のロールアウト完成を前提にしない。次の二つに分けてレビュー可能にする。

- **M1a (先に運用へ戻せる修正)**: メガ形態の整合、技固定の取得・保持・解除、部分的に読めた技の登録による補完、
  据え置きによる誤った保持。HP・選出・対応待ちの既存の防御を維持する。HPの新しい確率モデルまでは含めない。
- **M1b (共通遷移の最初の対応)**: §2.3の抽出と、自滅・HPコストの発動順序・自分のHP・ひんし・繰り出し要求。
  最初の対象はミストバーストとてっていこうせん、および同じ効果定義の技。先に倒された個体は行動せず、
  ひんし後の別個体がその予定行動を引き継がないところまでを含む。

M1bでは自分の損失を採点に渡す経路まで確認するが、任意の「自滅−N点」「残HP×係数」を追加して完了とはしない。
共通尺度での順位付けがまだ整わない場合は、遷移の実装受入と運用への採点接続を分け、M1aだけ先行できる。
その状態を「自滅技の提案改善が完了」とは記録しない。戦略的な価値・重みの変更は段B/Cの方式比較に残す。

上位3型の重み、変化技全般の評価、交代の全面的な再設計、RL加点の変更はM1に入れない。後続の順序はA→B→C→Dを維持する。
実装を別worktreeで進める場合、接続テスト中は本体・配信中のサーバー・モデル・実データへ反映しない。
軽い再現・回帰でもOCRや推論の負荷を見て、負荷試験・統合・重い測定は接続テスト終了後に行う。「単体テストだから影響しない」とは扱わない。

### 段A: 入力・形態・合法手と、局面の再現

M1aの対象。重いロールアウトの完成を待たずに進められる。

1. **メガ形態の整合**: フラグ・種族ID・石・タイプ・特性の不整合が生まれる経路を再現し修正する。形態の解決を共通化し、
   メガ後の能力値とタイプ一致補正まで照合する。見た目の名前は個体の同定用として分ける。
2. **技の固定と候補**: アンコール・こだわり・ちょうはつ・PP・初手限定等を、取得から解除まで通す。初手限定を「最後に使った技」だけで
   判定してよいか、行動不能のターンも含め確認する。自分の4技は当時の登録版と照合し、観測済みPP=0や技変化を上書きしない。
   登録と観測が矛盾する場合に現在のmy_team.jsonで過去を補わない。
3. **HPと残存戦力**: ひんし・選出枠・対応待ちを区別する。認識側の修正範囲と採点側の責務を分ける。バー推定の減点Bは暫定維持し、
   範囲を使う方式へ変更するときに、二重に罰しない設計として比較する。
4. **出力までの整合**: 最終の第一候補にも同じ合法手の検査を通す。`service.apply_advice_hysteresis`の据え置きは、個体・形態・技固定・
   ひんし等が変わったときに旧候補を残さない。まず誤った保持を直し、差6という幅の調整は採点尺度を固定した後に行う。

受入: 上記の実ログ再現と反例で、形態・能力値・技・合法手が一致すること。単体関数だけでなく状態→engine→serviceの経路を確認する。
既知の仕様違反はここで修正できる。勝率改善の主張はしない。

### 段B: 攻撃・交代・自滅の結果と、最小限の相手応手

初版の「構造の欠落」の中心。登録チームで実際に使う技・特性を先に扱い、効果ごとの対応状況を明記する。

1. **行動順と確率**: 先制・同速・トリックルーム・行動不能・命中・ダメージ乱数を枝分かれとして扱う。
   通常の単発技は整数ダメージ16通りを用い、連続技は回数・途中失敗・各打撃の効果を別に解決する。期待ヒット数を実ヒット数にしない。
   KO確率0/0.5/1と一律×0.25を、攻撃が実行されて各結果に至る確率へ置き換える。
2. **自滅・HPコスト・反動**: 発動順序、ひんし、失敗時の扱い、後続の繰り出しまで反映する。
   `残りHP% × 係数`だけを自滅の代償にしない。低HPでも有用な個体は残り、瀕死の個体を失って後続を無償で出す利益もあり得る。
   **先に倒された分岐の与ダメージは0**。HPが少ないことと行動前に倒されることを混同しない。
3. **交代と捨てる判断**: 登録・観測された実技で反撃力を計算する。通常交代は着地時の設置技と被弾、生存した分岐での反撃を評価する。
   ひんし後の繰り出しに通常交代と同じ被弾を課さない。先手／後手の交代技、無効・接触損失も区別する。
   現在の「最善交代+2」は行動前KO・無効を除外する修正済みだが、残る損失と利益を直接比較する方式へ段階的に置き換える。
   捨てる行動も、本人の実現可能な削りと後続の状態で比較する。必ず交代／必ず攻撃という規則にはしない。
4. **一撃を耐える効果**: ばけのかわの消費と自身のHP変化、タスキの消費、がんじょうの条件、連続技との順序を反映する。
   「対応表に名前がある」「最大ダメージが残HPを超えた」では受入にならない。ひんし・持ち物消費・次の打撃まで照合する。
5. **相手の応手の最小モデル**: 同じ応手集合を攻撃・交代・変化技に使う。判明技は所持が確定したのであって使用確率100%ではない。
   技の採用率は所持型の事前分布に使い、行動確率とは分ける。候補には合法な攻撃・変化技・交代を含め、各確率の合計を1にする。
   最初は固定した簡易方策と悲観側の結果を並べて診断し、未検証の確率を正しいと断定しない。

反動・ゴツゴツメット・いのちのたま等が生存やKOを変えるケースは、この段で対応する。「小さな差の決着」として後回しにしない。
受入: 後攻で倒された個体の攻撃が発生しない、倒された個体の予定行動を死に出しした別個体が実行しない、
反撃前に倒れた交代先に反撃利益を加えない、接触・自滅・連続技の順序が一致すること。未対応効果を成功扱いしない。

### 段C: 変化技と後続への利益

**技種別の専用処理 + 共通の状態遷移・局面評価**を採用案とする。大きな汎用探索を初手から導入する必要はないが、
技ごとの異なる単位の式をそのまま順位に足さない。専用の式は候補の優先探索や、打ち切り後の残存効果の見積もりにも使える。

| 技種 | 計算する差 | 避ける近似 |
|---|---|---|
| 積み | 今攻撃した場合と、積み→相手応手→次の行動の状態差。攻撃・耐久・速度・交代による解除まで含める | HP余裕×倒せる個体数だけで確定しない。相手の未選出を戦力として数えない |
| 設置 | 残りの交代機会、接地・無効・除去等を含む期待損失と、後続の行動順の変化 | ねばねばネットをダメージに置換しない。残数と交代回数で同じ機会を二重に数えない |
| 壁 | 実際の残りターン、持ち物、物理／特殊、交代や解除を踏まえた被害と行動機会の差 | 全ケースを5ターン固定にしない。打ち切りまでに計上した利益を将来分で重ねない |
| あくび・状態異常 | 遅延・免疫・既存状態・場・相手の居座り／交代を含む結果 | あくびを即時睡眠にしない。変化技なら必ず命中・有効としない |
| まもる・みがわり・ちょうはつ | 連続使用、消費HP、ターン経過による回復・削り、制限する行動と解除 | 単に1ターンしのいだだけで恒常的な利益を与えない |

比較は基準行動と同じ評価期間にする。まず1ターンを正しく解決し、積み・あくび・交代技等は効果が出る2〜3ターンまで限定して延ばす。
期間内に終わらない効果は共通の打ち切り評価へ渡す。計算予算を使い切った場合の処理も事前に固定する。

受入は「この実戦ではプレイヤーが積んで勝ったから積みを1位にする」ではなく、状態変化の一致と明確な条件差での判断変化で決める。
例: 上限まで積んだ状態では能力が増えない、壁が消費・解除される、受けるダメージと行動順が積みの前後で整合する。
戦略的な順位の良し悪しは§4の参照評価と方式比較で判定する。

**未評価の合法手**: 候補から消したり末尾へ落としたりしない。`unsupported`等を評価用データに持ち、通常の0点・8点と区別する。
初版は登録チームの全技を対応対象にする。それでも未対応候補や予算超過があれば、その決定全体を段Aの修正を含む固定の基準方式に退避する。
異なる尺度の旧スコアと新スコアを一つの順位に混ぜない。退避に従来の8点が残っても、それを検証済みの価値とは認定せず、退避率を記録する。
合法手が一つも確定しないときは不適切な行動を第一候補にしない。助言を出せなかった件数も評価の分母に残す。

### 段D: 型・応手モデルの改善、残る効果、限定探索の比較

- 相手の型は、持ち物・特性・配分・技・必要な形態をまとめた合法な共同仮説として持つ。個別使用率の上位を掛け合わせて実在性のない型を作らない。
  通常は最大3仮説を評価し、各重みと被覆率・残余確率を記録する。被覆率はモデル内の確率質量であり、真の型を含む保証ではない。
  3件だけで無断で100%へ正規化しない。
  スカーフ有無など順位を変える主要な仮説を取り落とす場合は代表の選び方を変え、それでも残余に敏感なら判定保留または基準方式へ退避する。
  残余の影響は上下界・感度として扱い、未知の確率を捏造しない。
- 上記の仮説の器と既知の持ち物による制約は段Bから使う。段Dではその重み・応手の行動分布の精度を改善し、重みを調整する検証を独立させる。
  発動・技固定・行動順で条件付けし、観測で否定された型を復活させない。
- 追加効果・回復・残りPP等は、登録チーム・頻出相手でKOや生存を変えるものを先行させる。残る対象を対応表から拡張する。
- engineとsearchが呼ぶ共通遷移の対応範囲を確認し、行動不能・メガ・選出3体・自滅等の前提が揃ってから限定探索を比較する。
  SEARCH_BLENDを上げるだけの実験はしない。固定点で同等とされた13件だけに有効性を限定しない。

## 4. 正しさと有用性の検証

### 4.1 仕様の受入: 状態遷移の一致

合成局面と画像で照合した実戦局面を用い、入力・合法手・行動順・両者のHP・ひんし・形態・ランク・場・持ち物消費を確認する。
ShowdownはローカルのChampions modとコミットを固定した参照実装として使う。実機と異なる既知の仕様は別欄にし、シミュレータ一致を実機仕様の証明にしない。

既存`tools/dmg_compare`は次の制約があるため、そのまま合格証には使わない。

- ばけのかわ等を未確認として除外し、タスキ・がんじょうでは「最大が残HPに届くか」を見る。今回必要な発動後の状態まで拡張する。
- 行動不能は未対応の遭遇件数、発動は対応記述の有無であり、その局面で効果が正しく解決した数ではない。
- 同速・多段技・状態効果・死に出しも個別の再現試験を加える。対象数、未確認、失敗を別々に報告する。

確定仕様の修正は、この受入と関連回帰で採用できる。戦略的な重み・近似評価が正しいことまで単体テストで主張しない。

### 4.2 局面別ロールアウト: 条件つきの参照評価

目的は「採点が失っている利益・損失」と「変更後の推奨の期待結果」を見積もること。勝率最大の候補を唯一の正解とは呼ばない。

**最初は作業全体で2時間上限の実現性確認に限る。** 接続テスト終了後に実施し、次の結果を残して止める。

- 完全なShowdown状態を一つ以上保存・復元し、同じ行動・乱数で遷移が一致するか確認する。
- 事前に選んだ実戦局面3〜5件の移植を試みる。HP・形態・選出・PP・状態効果等の欠落、移植できた範囲、所要時間を記録する。
  これは状態の移植試験であり、多数のロールアウトや正解候補の生成は行わない。成功した容易な局面だけに対象を差し替えない。
- 成功／部分成功／不成立を報告する。上限到達や不成立なら残る課題と費用を記録し、道具の拡張は次の判断へ回す。
  **段A/Bの仕様修正は§4.1と回帰で進め、実戦状態の復元ツール待ちにしない。** ただし戦略的な順位改善が検証済みとはしない。

実現性確認後に参照評価を実装する場合の要件は以下のとおり。

1. **再構成の可否を先に検証する**。当時の登録チーム・型・選出・形態・実HP・PP・技固定・場の残りターン・初手制限・ばけのかわ等の状態が要る。
   現在の`compact_to_engine_state`は簡約状態の復元であり、完全な対戦状態の復元ではない。過去の欠落を黙って初期値で埋めない。
   小数のHP%から実HPが一意に分からない場合も区間として扱う。
2. ローカルShowdownにはシリアライズ／復元処理があるが、実戦の簡約ログからの変換は別途必要。
   まず完全なシミュレータ状態で保存→復元→同じ行動・乱数による遷移一致を確認し、次に実戦由来の局面を少数移植する。
   変換が成立しなければ対戦途中からの評価は未実装・判定不能として扱う。
3. **当時の情報を守る**。後で判明した相手の技・持ち物・選出を、その時点の予測入力に混ぜない。
   画像等で正した「観測できた状態」と、隠された真の型は別データにする。真の型を知る評価を行う場合は上限診断として分離する。
4. 同じ初期仮説・相手応手の生成条件・乱数の組で候補を比較する。対応を記録し、乱数消費が分岐後に変わることも明記する。
   継続方策は候補版ごとに都合よく変えず、固定の規則とRLなど最大2組の条件を使う。双方とも実運用と同じ情報制約を持たせる。
   各条件の結果・平均・悪い条件での結果を分け、方策依存で順位が逆なら未決着とする。
5. **主に新旧の推奨間の期待結果の差と、その区間を報告する**。参照候補を選んだ試行とは独立した試行で評価し、最大値を選ぶ上振れを避ける。
   複数候補からの参照集合を作る場合は比較数と区間の作り方を固定し、差が確定しない候補を一意の敗者にしない。
   その集合は統計的に区別できない候補であり、同等性を証明した集合ではない。
   参照集合との一致は副指標。候補の選別と評価に同じ試行を使って「最善手との勝率差」を確定値にしない。
6. 数十試行は速度・分散の予備測定に限る。局面数×候補数×仮説数×方策条件×試行数×継続長で費用を積む。
   仮説を標本化して総試行数に含める方式なら二重計上しない。上限内で差を見分けられなければ判定不能のまま残す。
   試行を増やしても、10対戦由来の局面が独立した大量の実戦標本になるわけではない。局面を集計する区間は対戦単位の依存を考慮する。

当時の認識状態での旧版／新版と、画像等で確認した状態での旧版／新版を分け、認識修正の効果を採点変更へ帰属させない。
除外した局面、未対応効果、復元失敗、推奨なしは別の分母として報告する。容易な局面だけの成績を実戦全体へ外挿しない。

### 4.3 正式な方式比較と採否

戦略変更の主指標は既定どおり **候補版−固定した基準版の対応勝率差**。fold B、600戦/条件、2時間上限、300戦は中間確認のみ、
k本なら水準1−0.05/k、推定差≥0.05かつ区間下限>0で採用候補とする。区間上限<0.05は実用的改善を支持しない、それ以外は判定不能。
未完了や対応の不成立では採否を出さない。区間が0を跨ぐ結果を「負けていない」「非劣性を確認した」と呼ばない。

- モデル、登録チーム、選出方策、図鑑・効果表、Showdown、相手列、分割、DB、基準コミットを実験前に固定する。
- まず現在の登録チームを対象とし、確認できた範囲を明示する。別の構築・操縦方策への一般化は別の固定比較とする。
- RL加点は基礎修正中は現状を固定する。P1は「特定条件で0/×5に減らす5ポイント以上の改善が支持されず×25維持」であり、
  同等性や全チームでの有用性を証明していない。新しい局面評価を別の単位にする場合は×25をそのまま加えず、
  共通の尺度への接続を先に定義し、候補と対照の加点規則・換算を固定する。接続が未確定ならオンライン導入しない。
- 仕様修正済みの版を基準にしてから戦略方式を比較する。明らかなバグを残した版に勝つことだけで方式の優位性を主張しない。
- 1夜1主仮説。仕様修正ごとに600戦を追加せず、意味のある方式変更のまとまりを比較する。holdoutは方式固定後の最終確認1回に限る。

### 4.4 標本の独立性と実機での受入

既に分析した69決定は開発・再発防止用とする。不一致だけを選ばず、一致した決定と助言なしの決定も対象にする。
未使用の検証標本は今後の接続テストから対戦単位・時系列で固定し、同じ対戦の隣接ターンを開発と検証に散らさない。
初期は20〜30局面程度で手順を確かめるが、その件数を有用性の証明にはしない。固定失敗集と無作為標本を分ける。

実機では、新旧の版・状態時刻・形態・合法手・効果の対応状況・基準方式への退避を残す。既存の影の計算は隔離の受入前にONにしない。
まず保存局面をオフラインで評価する。10fps入力下で、入力処理率・状態の古さ・決定開始→有効な助言表示のp95・期限超過率を確認する。
エンジン単体の計算時間だけで受入せず、助言を出した割合と未対応・退避率も併記する。
