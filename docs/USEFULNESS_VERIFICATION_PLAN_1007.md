## 0. 判断の軸と資源

### 0.1 3 つの区分 (一覧の区分を採用)
- **正しさ**: 仕様・入力事実に合っているか → 壊れていたら直す。有用性の実験はしない (§10)。
- **有用性**: 単純な方式より判断・成績・作業が良くなるか → 比較条件を揃えた測定で決める。
- **費用対効果**: 改善が計算時間・遅延・学習費用に見合うか → 測定に費用の欄を必ず付ける。

### 0.4 データ分割の用途 (レビュー指摘 1)
season_pin (10/7 作成、seed 20261005) は相手の系統を **search / selection / holdout** の 3 層に分けている (`tools/team_build/opponents.py` の tiers)。
用途を次のように固定し、**最終評価用の holdout は、方式やモデルを選ぶ繰り返しの比較には使わない**。

| 用途 | 使う層 | 繰り返し使用 |
|---|---|---|
| 学習中の checkpoint・EMA の選択 (§3)、選出モデルの適応の checkpoint 選択 | selection | 可 (前提にしている) |
| RL 加点・選出方式・採点の構成要素など「方式」の比較 (§4、§5、§7) | search | 可。ただし同じ比較を何度も繰り返して良い方を選ぶと上振れするので、比較ごとに seed を変え、結果は全部記録する |
| 方式とモデルを固定した後の最終確認 (構築の採否と同じ) | holdout | **1 回だけ**。ここで方式を選び直さない |

§3 の旧記述「checkpoint ごとに holdout で評価して更新を決める」と §5 の旧記述「holdout で汎用と規則のどちらを使うか決める」はこの規則に反するので改めた。

### 0.5 採否の規則 (レビュー指摘 2)
各実験は始める前に次の 5 つを書く (§4 以降の表の「方法」欄に略記し、実験の記録ファイルに正式に残す)。

| 項目 | 既定 (実験ごとに変えてよい。変えたら理由を書く) |
|---|---|
| 主指標 | 対応比較の勝率差 (同じ相手列・同じ seed で条件だけ変える)。副指標は決定的な場面の第一候補の一致率など |
| 実用上意味のある最小差 (MDE) | 0.05 (助言の採点・選出方式)。構築の採否は従来どおり holdout の verdict |
| 初期対戦数 | 300 戦 / 条件。区間は Wilson または bootstrap で出し、n と一緒に書く |
| 追加測定の条件と上限 | 区間が 0 を跨ぎ、かつ区間の幅が MDE の 2 倍を超えるなら 600 戦まで足す (費用上限: 1 実験 2 時間)。それでも決まらなければ判定不能 |
| 採用 / 不採用 / 判定不能 | 区間が 0 より上なら採用、0 より下なら不採用、跨ぐなら**判定不能 = 現状維持** (点推定の大小で切り替えない)。複数条件を比べて最良を選ぶときは、選んだ条件を別 seed で 1 回再測して上振れを見る |

「件数だけ」の規則は使わない。「10 戦で第一候補が変わらなければ `model_pick_real` を外す」は表示を整理する運用判断 (有用性の判定ではない) として残し、
「10 run で較正規則を見直す」は較正標本の測定件数 (捨てた並びの測定 40 本以上) で区切る。

## 1. 着手順と時期

一覧の勧める順 (土台 → 実戦経路 → 取りこぼし → 評価相手 → 高費用の機能) を採り、時期を次の 5 段に割る。

### 1.1 段 0: 評価の土台 (10/7〜次の接続テストの前。2〜3 日、実装はサブエージェント)
§10 の正しさの確認と、§2 のログの追加。既存のログ (第17〜19 回 + 10/7 試験) に当てて動くことを確かめてから接続テストに入る。
影の計算 (`advice_variant` 行) は §2 の隔離条件 (採点の重みを引数で渡す改修を含む) を満たしてから入れる。満たせないうちは影の計算無しで接続テストを始める。

### 1.2 段 1: 実戦経路 (次の接続テスト 3 回、10 月中旬まで。約 40 戦)
影の記録 (RL 加点の有無・選出候補 3 種・相手の選出予測) を残す。40 戦たまったら C の再分析 (§4.2、§5)。
同じ期間に、run の無い夜に D の 2 本の**初期比較** (§0.5): **P1 (RL 加点 0 / ×5 / ×25)** と **選出方策 (規則 / 配布 / 登録チーム専用)**。
どちらも search 層で測り、方式を決めた後に holdout で 1 回だけ確認する (§0.4)。

### 1.3 段 2・段 3: 構築 run への相乗り (1 run に主仮説 1 つ、追加は合計 +3 時間まで)
毎 run に全部を載せる方式はやめ (レビュー指摘 7)、**run ごとに検証する主な仮説を 1 つ選ぶ**。費用は「条件数 × (候補 + 参照) × 対戦数 + 学習時間」で積み上げ、
段 2 と段 3 を合わせて 1 run あたり +3 時間を上限にする。常時載せるのは費用 0 のもの (較正標本は実装済みなので既定のまま) だけ。

| 相乗りの候補 (1 run に 1 つ) | 既存の仕組み / 足すもの | 対照の揃え方 | 費用の積み上げ |
|---|---|---|---|
| 較正標本 (捨てた並びを S8a だけ測る) | `BUILD_CALIBRATION_SLOTS=4`、`BUILD_CALIBRATION_VARIANTS=("generic",)` (実装済み) | 捨てた並びと通った並びを同じ S8a の条件で測る。種・技・型の段階で消えて並びにならなかった候補は入らないので、別途「絞り込みを一部緩めた小規模探索」(§6) が要る | 4 枠 × 100 戦 ≈ +0.7 時間 (常時) |
| 予備評価で早く落ちた腕の追い測定 | 無い → S8a の脱落腕を `--candidates` で続きを測る段を足す | 通った腕と同じ対戦数 (300) まで続ける | 3 腕 × 300 戦 ≈ +40 分 |
| S9 (修理) の対照 | 無い → S9 と同じ親から作る無作為変種を足す | **親・変更枠数 (S9 は `BUILD_REPAIR_MIN_CHANGES=2` なので対照も 2 枠)・型変更の範囲・候補数・測定予算を揃える**。「無作為 1 枠入替」では診断の有無と変更規模が混ざる (レビュー指摘 5) | 3 腕 × 100 戦 ≈ +15 分 |
| 同時探索 joint と従来 legacy の両方 | `--search-mode both` (実装済み) | 両方の最終候補を同じ測定に入れる。増えた候補の測定費用を数える | 探索段 +10 分 + 増えた候補 × 300 戦 (約 +40 分) |
| 相手の操縦 heuristic / rl、相手プール latest / mixed、相手の選出方策 規則 / model | 最終候補 (`BUILD_FINALISTS=3`) を条件を替えて測り直す | **同じ条件で参照チームも測る** (条件が変わったときの登録チームとの差を出すため。レビュー指摘 5)。mixed は構築に使っていない後続の実戦データで評価する | 1 軸: (3 候補 + 参照) × 2 条件 × 300 戦 ≈ +1.6 時間 (既存の条件の結果は再利用するので実質 +0.8 時間) |
| 選出モデルの変種 (規則 / 汎用 / production / fresh) | 参照の腕として毎 run 測っている (10/7: 規則 0.473 / 汎用 0.603 / production 0.533 / fresh 0.317) | 同じ参照チーム・同じ相手列 | 0 (記録を集計するだけ、常時) |

順位の相関 (過去 0.53) は補助指標にとどめ、各候補の「同条件の参照に対する差と区間」を中心に判断する。接続テストと重ならない夜に起動する。

### 1.5 段 4: 高費用の機能 (条件が揃ったときだけ)
- LLM 構想: 記事バンクを構想生成に接続した後に、規則のみと費用を揃えて比較 (今は 207 並び中 14 測って勝者 0。既定 off のまま)。
- 行動 RL の追加学習・チームごとの adapter: 学習を再開する判断があったときに §3 の規約で測る。

## 2. 接続テストで残すログ (段 0 で実装)

いま無いもの、または形を変えるもの。既存の行 (advice / display / events / outcome / rate / manual_fix / hp / version / session) はそのまま。
**実戦は比較の場ではなく記録の場**なので、どの行も「表示する助言」を変えない。

| 行・欄 | 内容 | 使う検証 |
|---|---|---|
| `advice_variant` 行 (advice 行とは別行、`advice_id` で紐づけ) | 同じ状態で RL 加点 0 / ×5 / ×25 (既定) の上位 3 と点差。**隔離条件** (レビュー指摘 4): (a) 採点の重みは環境変数ではなく関数の引数で渡す (`RL_BLEND_WEIGHT` を別スレッドから書き換えない。`check_advisor_player --no-rl-blend` も引数経由に揃える)、(b) 状態とモデル版を助言時点の snapshot に固定、(c) RL 加点より前の共通計算 (ダメージ・採点の基礎) を再利用し、**加点の後の KO 前割引・交代技補正まで再計算**する (最終点から RL 分を引くだけでは比較にならない)、(d) 待ち行列の上限 (既定 2 件) と打ち切り (次のフレームが来たら破棄)、スキップ理由と件数を `frames` 行に残す、(e) 前面のページで通常のフレーム (10 fps) が届く条件で遅延 p50 / max が悪化しないことを、接続テストの前に録画再生で確かめる | §4 RL 加点 (実戦で第一候補が変わる頻度と場面)。P1 のシム結果と突き合わせる |
| advice 行 (選出) に `candidates` | 規則 / 配布モデル / 登録チーム専用モデル / model_pick_real の 3 体と確率・予測勝率。既に一部ある (model_pick / model_pick_real / rule) ので欄を揃える | §5 選出方策。実際の選出 (picked) との一致は補助指標 |

| manual_fix 行に `overwritten_at` | 手入力の訂正が後の推定で上書きされた時刻 | §3 手動訂正の持続性 |
| 選出ラベル 3 値 | 相手の 6 体を **選出確定 / 非選出確定 / 不明** に分ける (今は 6 体 − 場に出た = 選出外)。「場に出たか」は別の欄 (`appeared`) に残す。3 体すべて判明した対戦だけの成績は「その部分集合の成績」として報告する | §10 ラベルの正しさ、§5 選出予測の正解 |

| シミュレーションの条件 | pin_models と season_pin で揃っている。manifest に相手方策・選出方策・モデルの版を必ず残す | 済 (記録の確認のみ) |
| 記事の出典・用途・合成データの隔離 | 合成記事はバンクの保存 / 読み込みで拒否 (テストあり)。許可 URL 以外は取得しない | 済 |

## 11. 無効・任意・未接続の機能 (一覧の 9 節)

すべて **E**。再び使うときの検証条件は一覧のとおりで、再実験はしない。再使用の引き金になるものだけ書く:
SEARCH_BLEND (評価方式の変更)、BELIEF_K (単一推定の誤りが実戦ログで多いと分かったとき)、HP の不確かさ (誤認識の分布が §2 の `hp_stale` で測れたとき)、
行動分布の RL (モデル更新時)、ESTIMATE_DAMAGE_ON_MOVE (表示されない場面に限定する再設計後)、少量データの選出適応 (費用削減が要るとき)、
チームごとの行動 RL (学習再開時)、選出計画 / テーマ (構築 run の探索の仮説を評価側に持ち込まない確認を先に)、別版の特徴量 / Set Encoder (選出モデル再学習時)、
学習した代理評価 / 転移量 (通常経路に接続してから)。

## 12. 費用のまとめ

費用は「条件数 × (候補 + 参照) × 対戦数 ÷ 約 1,500 戦/時 + 学習時間」で積み上げる。速度の概算は S8a の採点条件のものなので、
採点条件を変える実験 (助言操縦) は 50 戦の予備測定で更新する (§0.2)。既存の結果 (毎 run の参照の腕、既定条件の最終候補の測定) は再利用し、再利用できる条件を表に書く。

| 種類 | 内容 | 費用 (積み上げ) | 再利用できる既存の結果 |
|---|---|---|---|
| 段 0 | ログの欄・行の追加、ラベルの 3 値、採点の重みの引数化と影の計算の隔離、ダメージ照合の道具と確認表 (サブエージェント) | 実装 2〜3 日、対戦なし | — |
| 段 1 の夜 | P1 (RL 加点 3 条件 × 300 戦 + 層別 1 組)、選出方策 (search 層 3 腕 × 300 戦)。初期比較。追加測定 (600 戦まで) の余地を含む | 約 2 時間 + 追加測定 最大 1.5 時間 (run の無い夜 1〜2 回) | 選出方策の既定条件は 10/7 の参照の腕 (200 戦) |
| 段 1 の再分析 | §3〜§9 の C (ログ・保存フレーム・run 成果物) | 対戦なし。サブエージェントで並列 | — |
| 段 2・3 (run ごと、主仮説 1 つ) | §1.3 の候補から 1 つ (常時: 較正標本 +0.7 時間、参照の腕の集計 0) | **run あたり合計 +3 時間が上限** (例: 較正標本 0.7 + 相手の操縦 2 方策 × (3 候補 + 参照) 0.8 + 早落ち追い測定 0.7 ≈ 2.2 時間) | 既定条件の最終候補と参照の測定 (S8b / S10) |

## 14. レビュー (2026-10-07) への対応の一覧

| 指摘 | 対応 | 該当 |
|---|---|---|
| 1. 最終評価用の holdout を学習中の選択に使わない | season_pin の 3 層 (search / selection / holdout) に用途を割り当て、holdout は方式とモデルを固定した後の 1 回だけに限定 | §0.4、§3、§5 |
| 2. 300 戦を初期比較とし、採用 / 不採用 / 判定不能の基準を定める | 主指標・MDE・初期 n・追加条件・上限・3 値の判定を既定として明文化。件数だけの規則 (10 戦 / 10 run) を運用判断と標本数の規則に置き換え | §0.2、§0.5、§5、§6 |
| 3. 相手選出の予測は全分布と当時までのデータ | `opp_pick_pred` を全分布 + 6 枠 + 確定 / 推定 + バンク版 + 締切時刻に拡張。再評価は時系列分割。選出ラベルは 選出確定 / 非選出確定 / 不明 + `appeared`。部分集合の成績は部分集合として報告 | §2、§5 |
| 4. 影の計算の状態と設定の隔離 | 別行 `advice_variant`、重みの引数化、snapshot 固定、後段の補正まで再計算、待ち行列上限とスキップ記録、前面 10 fps での遅延確認。満たせないうちは影の計算無しで接続テスト | §1.1、§2、§4、§13-3 |
