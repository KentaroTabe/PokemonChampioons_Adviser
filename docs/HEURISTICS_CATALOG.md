# 競技ポケモンの定説カタログ — 実装状況と導入候補

作成: 2026-08-04。「読みを減らせる構築」(READ_BURDEN_DESIGN.md) に続き、
他の定説・セオリーを棚卸しして導入価値を評価する。

## 1. 既に実装済みの定説 (重複投資を避けるためのマップ)

| 定説 | 実装場所 |
|---|---|
| 勝ち筋・負け筋を常に把握する | endgame.py (勝ち筋/負け筋検出、アドバイスに🏁表示) |
| ラス1同士の詰み計算 | endgame.duel (パーティ診断の1v1もこれ) |

## 2. 未実装で有効そうな候補

### H1. 状況依存のリスク調整 「負けている時は分散を取り、勝っている時は堅く」

- **定説**: 不利な側は五分の択や乱数に賭けるべきで、有利な側は択を避けて
  確実に寄せるべき (ゲーム理論的にも正当: 劣勢側は分散が期待勝率を上げる)
- **現状**: search の recommended = 期待値と保証値の固定ブレンド
  (RISK_WEIGHT 定数)。局面の有利不利で変えていない
- **仕組み**: 現局面の静的評価 (または RL critic 値) で RISK_WEIGHT を動かす。
  優勢 (+0.3以上) → 保証値寄り / 劣勢 (−0.3以下) → 期待値〜アップサイド寄り
- **期待効果**: アドバイザーの実戦品質 (人間向け)。ボットのベンチには
  探索が操縦に入っていないため直接は効かない。実装コスト極小
- **測定**: 合成局面テスト + 実対戦の主観評価。数値目標は置かない (表示品質)

### H2. 死に出しプランニング (捨てる順番と無償降臨)

- **定説**: 倒されたら次を無償で出せる。「どれを捨てて何を通すか」の
  犠牲順は勝敗を分ける。勝ち筋のポケモンを雑に消耗させない
- **現状**: 交代スコアは「被ダメ予測/交代後の打点」のみ。アクティブが
  確定で落ちる局面 (何をしても間に合わない) で「誰を捨てるのが最善か」
  「勝ち筋を温存できているか」の評価が無い
- **仕組み**: アクティブ死亡確定の検出 (最速行動でも相手の予測打点で落ちる)
  時、交代候補のスコアを「次ターンの無償降臨価値」(出てくる相手への打点
  −被ダメ) に切り替え。endgame の勝ち筋判定と接続し、勝ち筋個体の
  犠牲は大きく減点
- **期待効果**: 中〜大 (終盤の詰み筋で人間がよく間違える判断)。
  アドバイザー向け。実装コスト中
- **測定**: 合成局面の回帰テスト + 実対戦レビューで「捨て択」の質を確認

### H3. 勝ち筋温存の探索評価 (H2の一般化)

- **定説**: 「勝ち筋は大切に扱い、通す盤面を作る」
- **現状**: endgame が検出・表示まで。探索の評価関数には未接続
- **仕組み**: search の葉評価に「勝ち筋個体のHP残存ボーナス」を加算
- **期待効果**: 中。H2の後に。探索ハイブリッド棄却の経緯があるため、
  導入時は択評価の表示品質としての価値が主 (操縦には使わない)

### H4. 対面操作 (ピボット技) の構築評価

- **定説**: とんぼがえり/ボルトチェンジ等の対面操作は「後出しじゃんけんを
  先出しに変える」= 読み負荷を構造的に減らす
- **現状**: 個別技として評価はされるが、構築レベルの「対面操作力」指標なし
- **仕組み**: read_burden Phase B に説明変数として追加 (チームのピボット技
  数・起点作り技数と読み負荷/勝率の関係を同じ枠組みで測る)。
  新しい測定インフラ不要
- **期待効果**: 読み負荷の相関が確定した場合の「なぜ」を説明する変数。
  構築推薦の質向上

### H5. 苦手特化カリキュラム (学習環境側で唯一の候補)

- **定説**: 「負けた相手を重点的に練習する」
- **現状**: selfplayプールの抽選は「強い世代優先」のみ。相手チーム
  (上位60構築) は一様抽選で、こちらが苦手な構築を多めに引く仕組みは無い
- **仕組み**: ベンチ評価の敗戦を構築別に集計し、負率の高い相手チームの
  抽選重みを上げる (例: 負率に比例、上限2倍)。学習が苦手を潰しにいく
- **期待効果**: 不明〜中。ベンチ全体勝率が上がるかは自明でない
  (簡単な相手で落とすようになるリスク)。**導入するなら ko報酬と同じ
  事前登録A/B必須** (δ=0.03, 共通乱数, 複数シード)
- **測定コスト**: スイープ1回ぶん (~6時間の本番停止)。優先度は
  ko効果の積み上がりが頭打ちになってから

### H6. 起点回避の警告 (積まれ検知)

- **定説**: 「その様子見は相手の積みの起点になる」。千日手に見える局面で
  相手が行動を変える典型例が積み技
- **現状**: 相手の積み技は択評価の行列に入っているが、「この行動は
  起点にされやすい」という明示警告は無い
- **仕組み**: gtheory の行列から「自分の消極行動 × 相手の積み」のセルが
  相手の最善応手である場合に ⚠表示 (「まもる/様子見は りゅうのまい の
  起点になります」)。計算済みデータの表示だけ
- **期待効果**: 小〜中だが実装コスト極小 (表示のみ)

## 3. 推奨順序

1. **H6 (起点警告)** — 表示のみ、即日
2. **H1 (状況依存リスク)** — 定数1つを関数化、即日
3. **H2 (死に出し)** — 中規模、次の接続テスト前に
4. **H4 (ピボット指標)** — read_burden Phase B に相乗り
5. **H3 (勝ち筋温存)** — H2の後
6. **H5 (苦手カリキュラム)** — 事前登録A/Bのコストを払う価値が出た時点で

見送り: PPスタール対策 (発生頻度が低い)、情報隠し (ボットに不要)、
天候ターン経済の精密化 (現状の観測で十分)、初手定跡のBC (コスト大効果不明)。
